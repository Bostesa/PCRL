## Discrepancies (every one found, however small)

None of these changes a reported number. D2 is the only one that bears on how a claim label reads.

**D1. Deployment schema refusals live in the CSV reader, not in the package** (check 6; minor, implementation vs text).
- **What the text says.** PROTOCOL §6 says deployment "refuses any other schema, SEX included". The docstring of `scm_bench/deploy_scm.py` says the package refuses any schema other than AGEP, WKHP, COW, SCHL, MAR, POBP in that order, and any forbidden column, SEX included.
- **What the package does.** `deploy_scm.release()` takes dictionary rows through `acs_replication.deploy.encode_raw`. It accepts rows that contain SEX: SEX is ignored and the output is byte-identical. It also accepts reordered keys. Only a missing field raises an error.
- **Where the refusals are.** Only the shared CSV reader `read_raw_csv` refuses SEX (any case), reordered, extra or missing columns. DEPLOYMENT_RESULTS' `refuses_bad_sex.csv` and `refuses_bad_order.csv` flags test that reader, not the packages.
- **No end-to-end path.** The source CSV runner rejects packages of kind `SCM`, so no single path from a raw CSV through an SCM package exercises the refusals.
- **No leak.** SEX never enters the computation.

**D2. Claim B's DEV utility gate is in the frozen code but not in the protocol text** (check 5).
- **The text.** PROTOCOL §9 lists the DEV 24-point gate under claim A only. Claim B reads "benefit vs NEURAL_RAW and vs H_LJ > 0 on both seeds, with nested 0.020".
- **The code.** The frozen `report.py` labels B `NOMINEE_FAILS_DEV_UTILITY_GATE` because that gate fails. Its hash equals the ANALYSIS_LOCK hash `7261c81c…`, so the rule was registered in code before any fit; it is not post hoc.
- **Under the text alone.** All four competitive clause lower bounds are above 0: NEURAL_RAW 0.00840 / 0.00241, H_LJ 0.01024 / 0.00744. B would then read `SUPERIOR_TO_ALL_ELIGIBLE` at margin 0.
- **What holds either way.** The nested 0.020 superiority is not established. The family interval for NEURAL_RAW s1, [−0.0024, 0.0341], includes 0.
- **The gate failure.** It comes from one point clause: UTILITY|occupation|Ucal|nll_excess|s0 = 0.010606 > 0.010. Its confidence status is UNRESOLVED (clause bound 0.0185, family interval [−0.00002, 0.0212]).
- **Fix.** The protocol text should state the gate for B.

**D6. Undeclared numerical conventions in `scm_bench/engine.py`** (check 3).
- **(a)** Admissibility uses `≤ B + 1e-15` slack (lines 210 and 218), which PROTOCOL §12.9 does not declare. §12.9 declares only the 1e-15 floor on remaining budgets and the 1e-12 term in the priority.
- **(b)** KL_B clips π_m to [1e-15, 1 − 1e-15] (line 157). This was inactive in the tests.
- **(c)** The constant `CAP = {'nll': 0.010, 'brier': 0.005, 'acc': 0.010}` (line 15) gives an accuracy value that contradicts the 0.005 merge budget. It is never referenced; `budgets()` correctly uses 0.005.
- **(d)** Absolute costs use global teacher constants rather than the per-cell sums of ‖t1‖², Σ t log t and max t listed in §4. This is equivalent, because the constants cancel in every Δ.
- **Not discrepancies, recorded for clarity:**
  - The merge "accuracy" cost is plug-in expected accuracy under the teacher law, which is what n·max μ implies, not label accuracy.
  - The priority uses cell-level income costs and admissibility uses grouped ones (declared in §12.9); they differ on most pairs.
  - The guard formula is exact for the fixed fine-cell law, as declared.
