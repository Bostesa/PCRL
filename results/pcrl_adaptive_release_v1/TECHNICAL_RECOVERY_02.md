# Task-only model loader recovery before common audit

The three new 2018 task-only baseline fits completed and were archived from source `1013edf863fa9b16e7e4b39622f38afd27230c89`. A read-only release-spec dry run then failed while loading the first model: invoking `task_baselines` with `python -m` had serialized `TaskOnlyPredictor` under Python's `__main__` module, which differed when `release_specs` ran as the next CLI. No common panel or outer assessment had started. The model file and its completion receipt remained intact and hash-verified; no task-only refit was made.

The loader now checks the saved file SHA before temporarily binding `__main__.TaskOnlyPredictor` to the exact canonical class during trusted private deserialization, then restores the caller's module. It rejects a conflicting class and still verifies the loaded type and training hash. A synthetic module-CLI pickle reproduces the failure and verifies identical token codes after recovery. This correction changes artifact loading only; the fitted predictor, quantizer, released token law, and scientific settings remain unchanged. The independently reviewed fix is staged before the common inner audit.
