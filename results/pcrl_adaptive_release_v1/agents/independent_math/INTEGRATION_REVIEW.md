## Resolved during review

1. `fit_b.run_center_from_roles` can produce `NO_ACCEPTED_SPLIT_ALIAS_A`. Initially `fit_controls.load_final_problem("B", ...)` recognized only `SUPPORT_LIMITED_ALIAS_A`, preventing required B controls/certification. The controls owner extended the verified A-alias path to both statuses, checks the B receipt's A-center SHA, and records the exact alias status. A parametrized synthetic fixture now covers both aliases.

2. `release_specs._load_controls` initially checked the center SHA as text but not the control unit's final cost/bank. The adapter owner now compares its U/PWGTP cost hashes and frozen-bank hash to the selected A/B problem; synthetic altered-cost and altered-bank receipts are rejected. This was a provenance correction, not a scientific refit.

## Named-score integration resolved during review

`release_specs.build_release_specs` emits canonical IDs such as `A_selected` and `A_control_D17`, deduplicating exact aliases. `selection.select_family_representative` and `select_route_candidate` require a score key literally `D17` on all three anchors. The coordinator added `selection.expand_named_scores`, which expands every declared alias from the canonical validation scores, explicitly maps `A_control_D17` to `D17`, and rejects missing/conflicting mappings. Its synthetic fixtures pass. The integration caller still must apply the pinned per-anchor alias map to each inventory-verified inner audit report before three-anchor selection; this review did not execute that future panel.

## Checks that hold, with scope

- B refined routing checks selected channel, partition, nuisance, and Linux-x86 parity receipts; the callable router accepts exactly local `x`, `ha`, stored T0 code, teacher posterior, and residual. Child rows that copy every parent row collapse to the T0 identity. Exact array equality prevents a false structural alias. A task-only control remains an original-person 17-token law evaluated privately from `RuntimeInputs(X_A,H_A)`; the returned public manifest omits that law.
- `selection.aggregate_differences` computes task as candidate minus comparator CE and sensitive recovery as comparator minus candidate CE, equal-averaged across three anchors. U/P point screens, H benefit, and D17 family fallback use registered signs and margins. The extraction path reads validation-selected scores, not `inner_check` task outcomes. Named-score expansion and matched family coverage still need integration before any broad claim.
- `outer_access.load_locked_outer_role` verifies the canonical local selection lock path/SHA, family manifest, three anchors, and private unlock receipt before `data.index` or prepared-row deserialization. The receipt is an **attestation**, not independent remote verification: `verify_outer_unlock` trusts `remote_verified: true` and a syntactically valid commit SHA. The coordinator must actually verify remote branch commit and lock bytes before creating that receipt, and retain the evidence. The loader alone does not prove the remote state.
- `certify_controls.certify_fixed_bank` re-solves the LP on the final frozen cost/cuts, replays selected Q and the MILP incumbent, and compares a feasible LP objective against a valid MILP lower bound using `lower_bound - LP_objective`. It retains unresolved lower bounds and labels the result numerical/fixed-bank, not a fresh-attack or population certificate. A selected Q from an earlier adaptation round can be feasible yet suboptimal on the final bank; the fresh LP solve correctly avoids treating it as the optimum. Checking the stored MILP `fixed_bank_cut_ids` against the final cut IDs would make its receipt more self-contained, although the completed-controls inventory and cost/bank hashes already constrain the normal path.

No source-level blocker remains in these reviewed paths. The coordinator must wire the named-score expansion to actual pinned per-anchor reports, verify remote lock bytes before writing the outer unlock attestation, and preserve the resulting receipts. No historical evidence or candidate outcome should be rewritten to absorb these corrections.
