# One-token release input schema

The deployed 2018 T32 encoder receives an original-person `RuntimeInputs(x_a, h_a)` record. `x_a` is the frozen-preprocessing 32-coordinate local `X_A` matrix, shape `N×32`; `h_a` is the four-coordinate unchanged A service, shape `N×4`. Both retain the verified archive dtype, order, and numeric values. A private input NPZ for the packaging CLI has exactly `x_a`, `h_a`, and one unique stable `release_ids` value per original person. IDs are a cache/replay key only, never a fitted feature or wire field. The CLI requires an owner-only private replay key of at least 32 bytes, held separately from the model and released record.

The 32×17 fitted channel and frozen T0 encoder stay private during per-person inference. The output NPZ contains **exactly `h_a` and `token`**: the service bytes are preserved, and `token` is one integer in `0…16` for each person. A sees `(H_A,Z)`; an authorized coalition can combine that output with its separately held, unchanged `H_B`. The person's true residence, SEX, RAC1P, `H_B`, hidden T0 state, Q row, RNG state, and private replay key are forbidden release inputs or outputs. The model architecture/channel may be published, but a person's row and key must not be shipped in the wire artifact.

One persistent token is the stated release. Keyed replay is a computationally pseudorandom implementation for immutable inputs and mechanism; the study does not establish protection for new independent draws, changed input snapshots, or composition with other releases. Exact summation over all 17 possible tokens is used by the **private evaluator**, not by the recipient as a probability-vector release. The only accepted production runtime is a compatible verified Linux x86 environment with the hash-pinned original encoder and fitted channel. A Mac float32 re-encoding of historical T0 is not an interchangeable input.
