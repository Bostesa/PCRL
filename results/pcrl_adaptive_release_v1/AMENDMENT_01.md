# Pre-Branch-B split-stability resource correction

Registered before any Branch B ACS split or candidate outcome was read. Branch A's anchor-0 round-0 fitting had begun; this change does not touch its data, coefficients, candidate, or selection rule.

The frozen protocol required a separate stability check for privacy-priced splits but also reserved `inner_check` for the common independent inner audit. Using `inner_check` outcomes to accept or reject a split would make that audit an input to the partition search. Branch B therefore evaluates split stability on the existing household-disjoint `inner_selection` role, while fitting/ranking split candidates on `coefficient_split`. `inner_check` remains excluded from Branch B partition and candidate choices before the common audit. This is a resource-routing correction; the global household assignment, outer-assessment lock, encoder access, support floor, budget, success endpoints, and controls are unchanged.

For every proposed split, the fitting and selection fixed-price gains are computed with their own normalized original-person U and PWGTP weights. A split can be accepted only if its fitting gain is positive and its `inner_selection` gain is defined and at least **25%** of its fitting gain. Rejected candidates and both gains remain in the private history. If no candidate meets this rule and the fixed 100-unique/100-effective-household support floor, the current parent partition remains. This ratio is an empirical stability filter, not a feasibility, held-out performance, or privacy guarantee. The same `inner_selection` resource may be used for adaptive development choices and is not a confirmatory sample.

Timing: 2026-09-24 03:08 UTC, before any Branch B ACS fit or split outcome. Affected units: Branch B splits and descendants only, all anchors. Prior Branch B scientific artifacts: none.
