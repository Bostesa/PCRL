# New direct-trial reporting adapter

The runner module is `compressed_income_safeguard.trial_reporting`. Its imports are metadata only. Person arrays, numerical imports, model deserialization, and forwards occur only in the authenticated new queue. The runner uses arithmetic primitives from its inherited `reporting.py`; it does not import independently written verifier arithmetic.

The one combined family is `compressed_income_safeguard`, with 216 original utility clauses and 24 CONSTRAINED/control recovery contrasts, K=240. Bootstrap draws are 2,048 duplicate-group draws from seed 2026101401, shared across all services and both fitted seeds. The inherited conditional development interval uses Student t critical value at 1−0.05/(2×240), degrees of freedom G−1, and bootstrap standard deviation with ddof=1. The paired seeds share people and are not independent populations.

All 18 reader names are mandatory in each local bank. The pair envelope includes 18 direct curves and the 36 literal local ignore-other aliases. All curves remain ATT oriented; no INNER orientation is performed. Reader envelopes reselect the maximum inside each bootstrap draw. Recovery controls depend on the U0_FULL and RAW_FULL real-control gates in both seeds.

## Queue entrypoints and input schemas

Every pin below is `{path, sha256}` and must appear in the active unit's `sources`. Exact worker spec bytes must themselves be registered. Private paths belong only in private specs.

* `--phase fixture --spec SPEC`: admission stage. Config has `unit_id` and `public_output`. Checks the registry counts, distinct two-seed membership, old identity refusal, complete reader keys, exact tie AUC, and duplicate-group multiplicities. It opens no scientific arrays.
* `--phase trajectory --spec SPEC`: admission stage. Config has `unit_id`, `manifest`, `checkpoint`, `geometry`, `seed`, `service`, `arm_id`, `epoch`, `private_output`, `public_output`. Model and geometry pins are verified before reads. It forwards the entire FIT role using the canonical batch1024 adapter before slicing fold2. It exports two task probability arrays privately and task aggregates publicly. U0/Ucal FIT caps never gate entry or nomination.
* `--phase nomination --spec SPEC`: attacks stage. Config has `unit_id`, `records` of 32 `{trajectory: pin, freeze: pin}` entries, two `starts` pins for exact RAW_HYBRID trajectories, and `public_output`. Each reader receipt must contain all18 readers and `ATT_validation.pair.contracts.complete_view` with reader_count54. All four arms use one common epoch across both source seeds. Selection enforces both tasks' incremental caps against the unchanged start and minimizes ATT pair envelope, occupation NLL, then epoch. Missing seeds fail. Epoch zero must be an exact metric witness.
* `--phase registry --packages ROSTER --output DIRECTORY`: metadata only. Roster is 18 entries containing `service` (or `arm_id`) and `seed`; no arrays are read. Output is `COMBINED_ENDPOINT_REGISTRY.json` and the returned family mapping contains its hash pin.
* `--phase report --spec SPEC`: attacks stage, after committed reporting seal. Config has `unit_id`, `manifest`, `reporting_seal`, `endpoint_registries`, 18 `packages`, `private_output`, `public_output`. Each package contains `service` (or `arm_id`), `seed`, and `freeze`, `release`, `scores` pins. Frozen binding `service_id` must match the package, and each freeze must occur in the canonical reporting lock. All sealed INNER truth pins, features, and both reference pins must be registered before truth access. The single reporting run derives all task probabilities from actual frozen released wires and generates private per-person vectors/scores plus safe aggregates.
* `--phase inference --spec SPEC`: attacks stage after the same seal. Config has `unit_id`, `reporting_seal`, `endpoint_registries`, `unit_input`, `arrays`, `private_output`, `public_output`. Use pins returned by the report. Output is public `COMBINED_INFERENCE.json`, `PRIMARY_ENDPOINTS.csv`, and private endpoint draw arrays.

The report's private `REPORT_INPUT_INDEX.json` uses tables `metrics__SERVICE__Sseed`, `scores__SERVICE__Sseed`, `truth`, and `control_gates`. Utility vectors use `own__TASK__accuracy/nll/brier`, `REF_U0__TASK__accuracy/nll/brier`, and `REF_Ucal__TASK__accuracy/nll/brier`. The independent verifier owns separate arithmetic and may compare these vectors with its independently recomputed outputs.

The strongest point eligible control is selected by smallest paired complete pair AUC, with exact ties resolved RAW_PROJ, RAW_HYBRID, RAW_FULL, ORDINARY, LOCAL_TWIN, TASK_ONLY, U0_PROJ, U0_FULL. No historical point exclusion is carried into this registry.

## Exposure and limits

This is an exploratory direct safeguard trial on repeatedly used Adult development people. Source training, public prior results, internal selection and earlier occupation assessments are already exposed. New locks, seeds and fits do not create fresh confirmation. FIT fold2 is an incremental selection proxy on people already seen during source training. Task caps against both U0 and Ucal remain mandatory in final reporting.

The frozen income wire's predictions and utility uncertainty are shared across continuation arms. Occupation training cannot resolve an income utility interval. Completion, component observations, whole-release criterion, and deployment/custody must be reported separately.

No numerical or scientific worker was executed by the reporting agent. Syntax compilation of the new module succeeded. Root owns all queued engineering and scientific execution, registry commit, reporting seal, and outcome claims.
