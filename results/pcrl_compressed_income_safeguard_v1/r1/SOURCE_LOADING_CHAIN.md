# Source metadata and queued admission

This is an exploratory direct safeguard trial on repeatedly used Adult development people. Source training, public prior results, internal selection and earlier occupation assessments are already exposed. New locks, seeds and fits do not create fresh confirmation.

The source inventory preparation reads only private JSON manifests and restore-index metadata. It checks presence and file size, and hashes JSON/code metadata. It does not read, hash, deserialize or copy model/checkpoint/NPZ bytes, launch fits, or open INNER truth. Current presence is metadata evidence; the queued admission receipt supplies numerical evidence.

The reduced roster contains exactly four required source instances. The RAW sources are strength 0.3, epoch 5. The U0 anchors are the exact previously admitted zero-update checkpoints. A missing source fails admission; another historical trajectory cannot substitute for it. The prior OB1 source/roster schemas and TCR1 checkpoint schema are retained. The new campaign identity is bound separately in the private manifests and the CIS1 source-admission output.

## Exact authorized loading chain

1. The new durable scheduler authenticates `admission_worker.run` at stage `admission`. Manifest/roster hashes and their mutual binding are checked. The metadata whitelist rejects omissions, duplicate/extra source instances, changed expected hashes, seed/family/epoch mismatches, old campaign identity, forbidden fields and missing source metadata before numerical imports.
2. The local useful-source restoration calls this campaign's `source.pinned`. It verifies source COMPLETE/model/head/record/public-schema pins, copies only the inherited float32 encoders, and folds the deployed logistic heads with the inherited float64 arithmetic. It never calls the old useful loader bound to the predecessor queue.
3. The role-specific `source.load_role` verifies exact allowed file fields, raw83 dtype/schema/nonfinite checks, row/group counts and label/reference pairing. The FIT duplicate-group folds retain the inherited salt. Source seeds are paired on the same row and duplicate-group identifiers; all role overlaps must be empty.
4. The worker checks U0 probabilities against original fitted heads and stored U0/Ucal predictions for all three authorized feature roles. These are prediction-reference checks. FIT labels alone support source task metrics and stratum checks.
5. Each required checkpoint is hash-verified through the new pin loader before the inherited TCR1 deserializer is called. Payload identity, class order, finite tensors and U0 tensor alias equality are checked.
6. `wires.bind_geometry` derives each basis solely from that checkpoint's actual head. The binding includes campaign, source seed, checkpoint hash, canonical wire-contract hash, full public head/basis geometry and exact head-tensor hashes. Code hashes are frozen by the campaign's locks and queue unit.
7. `wires.forward_role`, with fixed batches of 1024, evaluates the declared full, hybrid and projected wire contracts on authorized role features. Both NumPy geometry audits and actual Torch recipient outputs must preserve logits/probabilities within the inherited tolerance and decisions exactly. The RAW hybrid income must equal RAW_PROJ income literally; RAW hybrid occupation must equal RAW_FULL occupation literally. Frozen income and basis checks run after role forwards. Admission supplies no new fit or selection evidence.

## Verification and custody limits

Nine data-free metadata guard checks passed, and the worker compiled. These checks do not establish numerical source admission or an Adult benefit. ROOT exclusively queues numerical admission and integrates SOURCE_ADMISSION.json.

All required originals were present at metadata inventory. A private restore map records exact-hash aliases from the predecessor's versioned snapshot receipt. No restore or backup copy was performed during source preparation. A stale or missing original must be restored under the new queue and then admitted; the snapshot receipt alone is insufficient numerical evidence.
