# R19 unified primary endpoint schema proposal

Status: `D_ROWS_VERIFIED; A_ROWS_NOT_RUN`. R00 owns any shared `PRIMARY_ENDPOINTS.csv`. This proposal keeps absolute endpoints and simultaneous contrasts in one **tagged table**, while retaining each family's original interface, registered clause ID and uncertainty scope. It does not rank D against A.

`PRIMARY_ENDPOINTS_D_UNIFIED_PROPOSAL.csv` (SHA-256 `4ec0adda1dc9aa83df64093e51cfdbcda842730820e32d1ed94da1820d68cd12`) contains 665 D rows: 56 absolute task rows, 42 absolute local/pair SEX AUC rows, and all 567 fixed K567 signed contrasts. `build_primary_endpoint_proposal.py` regenerates it from the three hash-pinned R19 D exports and checks the clause order against sealed R02 `D_FAMILY_ORDER.json` SHA-256 `32bc44199da6035c0afa226dbda78d0728ce51f2921a51a0ef2fe5cd6e9573b1`. No A result is inserted.

## Columns and meanings

| Column | Meaning |
| --- | --- |
| `schema_version`, `record_id`, `record_kind` | Fixed schema tag, unique namespaced ID and one of `absolute_task`, `absolute_recovery`, `signed_contrast`. An inference clause uses the exact locked ID after `D:signed_contrast:` or future `A:signed_contrast:`. |
| `family`, `service_contract`, `comparison_scope` | `D` or `A`; actual release interface; whether a contrast is same-capacity, cross-capacity diagnostic or arm versus reference. These fields do not grant comparator eligibility. |
| `arm_id`, `other_id` | Canonical family arm and, for a contrast, its second named term. D absolute arm `D_K` corresponds to display label D-K; A uses locked `A_*` IDs. |
| `summary_id`, `seed_id`, `draw_id` | D uses `s0`, `s1`, `mean` and blank draw. A preserves the full registered `s0_d0` … `s1_d2`, `s0_mean`, `s1_mean`, `mean` summary IDs and each actual release realization. Model seeds and draws are not independent people. |
| `task`, `reference_id`, `view`, `metric`, `contrast_kind`, `contrast_convention` | Task/ref for utility, `r1`/`r2`/`pair` for recovery, `accuracy`/`nll`/`brier`/`auc` for signed clauses; raw contrast type and sign (`candidate_minus_reference` for utility; `first_minus_second` for recovery). |
| `accuracy`, `nll`, `brier`, `accuracy_delta`, `nll_excess`, `brier_excess` | An `absolute_task` row holds the three task metrics against one named reference. `accuracy_delta` is **candidate minus reference**, reversing the R19 point CSV's `accuracy_drop` sign. NLL and Brier excess retain candidate-minus-reference sign. |
| `sex_auc`, `reader_id` | An `absolute_recovery` row holds the strongest frozen complete-view reader's AUC and ID for one view. It is a point estimate, not an absolute AUC confidence interval. |
| `point_estimate`, `interval_lower`, `interval_upper`, `interval_status` | A `signed_contrast` row holds the registered raw difference and simultaneous bounds. Utility statuses use inclusive caps; recovery contrasts remain `RAW_SIGNED_INTERVAL_UNINTERPRETED` until a named control/candidate direction and eligible comparison are applied. Absolute task `interval_status` is the three-clause conjunction; absolute recovery says no absolute AUC interval. |
| `task_reference_point_status`, `all_task_point_status` | The row's task/reference point conjunction and the arm's full task/reference point conjunction; blank for raw signed contrasts. `PASS_POINT` is never an interval pass. |
| `source_point_receipt_sha256`, `source_interval_receipt_sha256` | Public independent receipt hashes, never private paths, person-level arrays or predictions. |

Unused columns are empty, rather than zero. The D table includes every registered signed recovery contrast even when its direction does not match a prospective claim. The R04 independent interval receipt SHA-256 is `3c8ad07fbedcc62044c538451f2ffd4292f0b95088120fc9c26206c02c7d5efa`. It reports 567 clauses, 2,048 paired group resamples, both-seed point parity and one fixed-family simultaneous critical value. D's hard code and F continuous wire remain distinguishable in `service_contract`; comparisons involving F are marked cross-capacity diagnostics.

## R04-to-R19 interpretation checks

1. R04's D `all_seven_point` task records contain raw task metrics and its `point_gate` has per-reference excesses. The 56 R19 rows repeat those exact point values. K567 raw accuracy clauses use **candidate minus reference**, while the earlier R19 task CSV names the opposite quantity `accuracy_drop`. The unified table writes `accuracy_delta=-accuracy_drop` and verifies that value against the independent K567 point.
2. R04's 42 local/pair values are absolute reader-envelope AUC **points**. K567 supplies 315 signed *difference* intervals, not absolute AUC intervals. The unified table keeps those as separate rows; interpreting a positive raw contrast as privacy benefit without checking which arm is candidate would be wrong.
3. D's 567 signed clauses include 252 utility, 189 arm-pair AUC and 126 arm-versus-U0/Ucal AUC clauses. Only 252 utility clauses receive generic cap statuses: 42 `PASS`, 43 `VIOLATION`, 167 `UNRESOLVED`. The other 315 remain raw. D-K's mean occupation U0 NLL lower 0.010368 > 0.010 and Ucal Brier lower 0.006994 > 0.005; mean T-minus-D-K pair AUC 0.034429 has interval [0.013719, 0.055138], unresolved for the 0.020 benefit target. All six hard-code arms fail the point utility gate. There is no competitive or joint-design D result.
4. R04 includes class recall and majority gain in the source task records, but the 56-row R19 task export does not carry them. A shared completeness report must import or independently replay those fields separately; a blank primary-endpoint column would not prove usefulness.

These are repeatedly used Adult development rows and fitted-model conditional intervals. R00 should pin the final source hashes and complete unit ledger before publishing a shared table; this R19 proposal is not a final verdict.
