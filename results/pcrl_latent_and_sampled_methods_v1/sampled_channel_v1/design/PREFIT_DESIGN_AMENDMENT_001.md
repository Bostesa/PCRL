## One common source and output contract

Use the globally canonical T* bank and action map in `MECHANISM_SPEC.md`: source fine cells are 64/641, output banks are 16/321 for seeds 0/1, and each recipient has at most four class-preserving actions. Every paired law is aggregated over actual public code IDs before expected task loss, entropy or Bayes recovery. The central controls may read both frozen U0 score vectors and both fine cells at the provider. Strictly local factors receive only their own score vector, fine cell and task label through a separate fit capability. No control appends U0 or sends the private input cell. New task-only fit capabilities have no SEX field; historical T* remains an inherited task-objective source whose old fit path did access SEX.

The central feature vector is the eight score coordinates plus clipped entropy and top-two margin for each recipient, in the fixed 12-coordinate order of `MECHANISM_SPEC.md`. A central factor is `12 -> 16 tanh -> 4` with fixed padded local action slots, 276 scalars. Two product factors have 552 scalars and condition on the same provider feature vector. A local income factor is `4 -> 16 tanh -> 4`, 148 scalars, using only its two score coordinates and two summaries. A local occupation factor is `8 -> 16 tanh -> 4`, 212 scalars, using only its six coordinates and two summaries. Locality is enforced at the input object boundary; zeroing the other score inside a two-score input is insufficient.

Each freeze-first stage-one factor is central and has 276 scalars. Stage two uses a central factor and adds a trainable `Z_first x 16` embedding of the **actual emitted first global canonical code** to its hidden preactivation. SEQ12 has 808 total scalars; SEQ21 has 5,688. The stage-two input is the two frozen score vectors and sampled first public code, not the source fine cell, unsent action position, first probability law or a favorable selected draw. The two order-specific models have unequal capacity and the same whole-arm compute ceiling. Report FIT first-code coverage and the full frozen first-law probability mass on unseen codes; after freezing the configuration report INNER unseen mass without design changes. A larger sequential model may be undertrained at the common ceiling; neither order is an optimality claim.

Initialize the entire stage-two embedding deterministically as `E0[z,j]=bank_first.probability[z,j mod K_first]` for canonical first-code ID `z`, `j=0..15`, float64, where `K_first` is 2 or 6. Use no embedding weight decay. Rows whose code never occurs in the single precommitted cached first FIT draw remain **bitwise E0** in the fitted checkpoint and at deployment; a synthetic absent-code test and full-law replay must verify this. The stage-two policy must be defined for every admitted first public code even if that code was unseen in its sampled FIT draw. A changed unseen row or unhandled code makes the sequential arm incomplete. The first-stage checkpoint and FIT stream/draw are frozen before stage-two fitting. Full final-law expected losses and `G` integrate every possible first code and determine checkpoint feasibility; selected-draw training loss alone cannot qualify a checkpoint.

## Bounded optimization schedule

All optimizers use float64, one numerical thread, full OSF_DEFENSE_FIT batches, two independent named starts, 300 total scheduled update rounds per start for a paired arm, and exact fitted-law checkpoints at update 0, every 25 rounds and terminal update. A cutoff, numerical failure, missing required start or failed full-law replay makes the arm incomplete; a partial incumbent remains diagnostic. Selection considers exactly feasible completed checkpoints only, using the arm's sealed primary objective and deterministic start/update ties. Feasibility means every expected FIT loss is **at or below** the corresponding both-reference cap, and for protected arms every applicable local fitted-law guard is at or below identity. An epsilon can classify roundoff for diagnostics but does not relax these scientific bounds.

| Arm | Per-start scheduled updates | Scope and checkpoint rule |
|---|---:|---|
| JOINT-STOCH and TASK-STOCH-CENTRAL | 300 for each of two starts | One `12 -> 16 tanh -> 16` padded joint gate, 480 scalars. Select the lowest replayed protected `J` or task-only empirical rate among completed feasible checkpoints. |
| PRODUCT-CENTRAL | 300 for each of two starts | Update both 276-scalar central factors in each round under the same exact pair law, caps and protected `J`; both factors' checkpoint is atomic. |
| LOCAL | 150 per start for each recipient, two starts per recipient | Fit each own-only factor independently on its task cap and local fitted-law `G`, then compose the two selected new factors. Both local fits must complete; exact composed pair replay and fresh pair attack are required. |
| SEQ12 and SEQ21 | 150 per start for stage one, then 150 per start for stage two | Stage one fits its own central task/local `G` and is selected/frozen before the precommitted FIT draw. Stage two fits with both scores and the actual first emitted code. Select stage-two checkpoint only by full final-law caps, local guards and protected pair objective; never reselect stage one using stage-two outcomes. |
| JOINT-DET and TASK-DET-CENTRAL | 300 STE updates per start, two starts, plus at most 64 fixed output-bias trials per start | Separate deployable hard gates, 480 scalars. Replay hard outputs at the same 25-update schedule; polish from each start's best feasible checkpoint, or terminal checkpoint as repair. A trial must remain exactly feasible and improve the sealed objective/ties. No per-person reassignment or rounded JOINT-STOCH start. |

For the stochastic central gates use full-batch Adam with learning rate `0.01`, augmented constraint penalty coefficient `rho=100`, dual update every 25 steps, gradient-norm ceiling `5`, and no weight decay. Initialize hidden weights and biases from the precommitted per-arm/start RNG as normal with standard deviation `0.01`; initialize output weight matrix exactly zero. Start 0 has output bias `+4` only in padded slot 0 (identity biased); start 1 has all output biases zero (exact uniform over valid masked actions at update 0). Factor gates use analogous exact-zero output matrices and a `+4` first-valid-action bias in start 0, zero biases in start 1. Independent fit seeds, RNG algorithm, arm-stage domain and exact checkpoint tie order must be bound in R00's effective lock before fitting; do not choose them from observed outcomes. The deterministic trainer uses the same two starts, optimizer/update/replay schedule and matched whole-arm CPU ceiling with its separately frozen STE and bias-polish rule in R13's `CONTROL_SPEC.md`. No post-channel calibration or utility-cap retuning is permitted.

The update counts are equal at the **paired-arm level** as 600 joint rounds or 600 factor/stage rounds; this does not imply equal gradient work, parameter count or convergence. PRODUCT updates both factors in one round. LOCAL and SEQ divide their 600 rounds across their two constituent fits. DET additionally performs bounded hard replay and bias trials. Every arm receives the same **whole-arm process-CPU ceiling** including data preparation, both starts/stages, replay, checkpoint serialization and release-policy validation. A stage may receive only the remaining CPU; there is no independent CPU reset. R03 must time role-sized synthetic full workers and report max wall/CPU/RSS before R00 fixes the numeric ceiling.
