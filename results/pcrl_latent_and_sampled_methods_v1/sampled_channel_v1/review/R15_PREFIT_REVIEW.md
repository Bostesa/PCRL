## Scientific boundary

The proposed service is a centralized provider reading both permitted frozen task-score vectors, drawing one output pair, and transmitting to each recipient only its sampled global output code, fixed bank probability/decision and declared metadata. The provider may use both score vectors to form its law. A score-only release cannot claim privacy for a feature-sharing interface. SEX may supervise fitting but is not an inference input.

The source token or fine cell must remain private. The public code must be a **global identity of the transmitted fixed probability vector and decision**, independent of input token and input-local action index. Exact duplicate public values are one public code. An ordinal renaming of input-local actions would preserve the leak. Near-equal vectors with distinct transmitted bytes remain distinguishable unless the public bank is frozen to one exact vector before fitting.

The same-class action set reveals each recipient's frozen predicted decision by construction. The aligned pair of decisions therefore gives an ideal-reader privacy floor. A finite attack estimate below its decision-only reader is evidence of reader weakness or sampling error, not a mechanism that erased the disclosed decisions. The class-only reference may fail mean utility and must not be called an eligible matched control merely because it has low recovery. Fitted-law Bayes accuracy, observed SEX AUC and mutual information are distinct quantities.

## Required adversarial cases

1. Two distinct source tokens with the same permitted public vector. They must yield the same global code ID if that vector is transmitted, including when reached as different local action positions.
2. Two local actions producing the same public output pair. Their probabilities must add in the output law before local/coalition privacy and sampling comparisons. Duplicates must not cause a second normalization or change expected utility.
3. A source-specific action index or fine ID planted in a metadata field. The wire adapter and complete-view builder must refuse it, including strings, variable code length, fallback and version/routing fields.
4. A bank with `p_a(y)` varying across actions. `sum_a q_a[-log p_a(y)]` and `sum_a q_a Brier(p_a,y)` must be scored for the sampled contract; the loss of `sum_a q_a p_a` is lower by convexity in general and cannot be substituted.
5. An absent fitting class with a registered reserved source bin and same-class output. Identity/deployment must cover it without a raw-score fallback or class-changing code.
6. A complementary coalition clue and a no-complementarity law. The pair objective/attack must detect the former; neither case licenses a demand below the disclosed decision-pair floor.
7. Repeated request for one person/service key. The same cached sampled output must be served, or the threat model must explicitly change and be tested. Duplicate-group and paired-recipient alignment must be deterministic under the frozen sampling plan.
8. A fitted joint kernel compiled into each sampling order. Both exact compilers must reproduce the same public output law, including a zero-probability conditional convention. These are engineering aliases, not new scientific wins.

## Claim limits

An expected utility constraint is exact only for the fixed empirical law and public bank. A nonconvex fitted gate has no global joint optimum certificate from alternating updates. Three predeclared complete draws measure mechanism variation; they are not three populations and no best draw may be selected. A favorable joint result must beat both freeze-first **design** orders and the strongest non-joint matched control; it cannot claim superiority to unrestricted sequential sampling because every joint finite kernel factors in either order. A stochastic-specific result must also survive a seriously optimized deterministic same-bank ablation. Missing required controls leave the corresponding attribution incomplete.
