## Objective and controls

- Primary D-K must use nonnegative *biased* empirical MMD on numerically hard bits for each local view and a product of recipient kernels on aligned pairs. Seal bandwidths, scale, weights and any deterministic gradient-ratio coefficient calibration before outcomes. A local-only kernel average is not a coalition objective; independent purpose minibatches destroy the paired clue.
- Static check of R16 kernel source SHA `8e1cea0c7bfdbfedd5b5d6a2ef1c9cc1832964b11c22540effaf16e4c5a0c58d` and test SHA `dca19ec7d0aeeb5e7128f9744a0ccf48ef9f094679cd62f715a4755aad55234a`: the four fixed Gaussian scales, biased diagonal-inclusive formula, product pair kernel, numerical hard-bit guard, and float64 differentiable ST path implement that mathematical objective. The API receives no row IDs, so caller-side identical-person/order assertion remains mandatory. This is static arithmetic review, not Adult validation.
- XOR arithmetic oracle: with independent fair bits `R,S`, let `c1=R`, `c2=R xor S`. Each local conditional law is identical, while the pair laws differ. For a normalized one-bit kernel with cross-state value `rho<1`, product-kernel population MMD squared equals `(1-rho)^2>0`. Test this by independent enumeration, and test that zero privacy weight gives the exact same continuation as T under identical seeds and update order.
- T must be seriously task-trained with the same mapper/head, teacher distillation, capacity, checkpoint rule, initial source, and permitted internal task-validation selection. Clone its selected initialization into D-K, L, S12, S21 and applicable C. Give T the same continuation updates/exposure as privacy arms. Do not let the protected arm get extra task updates, starts, or validation choices. A task-only control with no continuation is weak.
- R06 proposes warm and T continuation selection at epochs 5/10/15/20 by mean uncalibrated task NLL, then a common full-FIT warm refit and fixed continuation count. R07 repaired initial every-epoch CE+KL selection, added full-FIT mode, selected-T initialization guard, `lambda/3` local weighting, sex-free T guard and one-group batch refusal. An initial `array_split` schedule produced about 251–254-person batches; R07 changed it to exact 256-person slices with the proposed short-tail rule. The runner must seal/hash the same actual plan across T, D-K, L, S and C, including the group-aware tail handling performed outside T's sex-free trainer, and verify update counts.
- Sequential training must use the actual fixed hard first release for each aligned defense-fit person, not a recomputed soft proxy or a newly drawn first code. Freeze the first mapper/head and its hash; train the second with local and pair terms; verify each recipient gets equal optimizer updates and task opportunities. Runtime release remains purpose-local.
- No inherited Team D ordinary *adversarial hard-code* C implementation was found in its prior source. Its RAW-J comparator uses a separately trained raw-input encoder and a continuous release; it cannot fill C's same hard-code architecture/capacity role. If an inherited D-C source is found, identify its exact objective and decide whether it is C or a distinct optional candidate before the fit. Missing C leaves a competitive claim incomplete.
