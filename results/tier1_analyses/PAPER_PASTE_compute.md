## Paper paste — §5.1 (or Appendix) compute cost

We measured the wall-clock and parameter overhead of running PCRL in place of $k$ independent compliant encoders. On Adult the joint PCRL run takes $1873\!\pm\!23$~s per seed to fit all $k\!=\!3$ purposes, against $34$~s for a single LAFTR encoder (so $102$~s for the $k$-independent baseline); the parameter count is 69,412 for PCRL versus 129,804 for $k$ independent encoders, a ratio of 0.53. Forward-pass latency on MPS measured over batches of 1000 samples is $0.88$~\textmu s/sample for the adapter-routed encoder versus $0.36$~\textmu s/sample for the bare backbone. On HMDA the joint PCRL run takes $3861\!\pm\!72$~s per seed to fit all $k\!=\!3$ purposes, against $72$~s for a single LAFTR encoder (so $216$~s for the $k$-independent baseline); the parameter count is 65,113 for PCRL versus 119,241 for $k$ independent encoders, a ratio of 0.55. Forward-pass latency on MPS measured over batches of 1000 samples is $0.62$~\textmu s/sample for the adapter-routed encoder versus $0.32$~\textmu s/sample for the bare backbone. On Diabetes the joint PCRL run takes $3160\!\pm\!73$~s per seed to fit all $k\!=\!3$ purposes, against $142$~s for a single LAFTR encoder (so $425$~s for the $k$-independent baseline); the parameter count is 115,165 for PCRL versus 154,829 for $k$ independent encoders, a ratio of 0.74. Forward-pass latency on MPS measured over batches of 1000 samples is $0.61$~\textmu s/sample for the adapter-routed encoder versus $0.36$~\textmu s/sample for the bare backbone. The pattern is consistent across the three tabular benchmarks: PCRL trades a higher per-seed training cost (the constrained Cotter loop over all purposes is more expensive than $k$ independent LAFTR runs) for a sub-linear parameter count, because the $|P|\!\times\!\text{rank}$ LoRA adapters are an order of magnitude lighter than $|P|$ full encoders, and for an inference path that touches the same backbone weights regardless of which purpose is requested. The latency overhead from the adapter forward hook is in the single-microsecond range and would shrink further on hardware that can fuse the two ``Linear`` calls inside the adapter into the host ``Linear`` they sit on.
