# Selection lock design (no outer outcomes opened)

The existing `inference.family_manifest` is the endpoint enumerator. The coordinator nominates **at most two configurations**, each one common across all three anchors, from registered inner-development validation. A per-anchor hyperparameter choice would add unregistered selection flexibility. A candidate that is an exact Q alias of a comparator remains visible but cannot satisfy the required material AB/RAC1P improvement.

Before writing `SELECTION_LOCK.json`, verify for every selected configuration and each matched comparator:

1. Completed fit and independent inner-pilot receipts exist for anchors 0, 1 and 2, and their full artifact hashes replay. Pin all three Q file/array hashes, exact aliases, fitted decoder/reference hashes, five role-specific selected audit-route model hashes, inner split SHA, original/sanitized 2018 input pins, source-tree SHA, protocol lock SHA, and any executed sidecar registration SHA.
2. The matching unprotected optimizer, historical D17, a validation-selected feasible deterministic release and a validation-selected matched gradient adaptation are in each slot's comparator list. If any is missing, record the resulting broad primary claim as not assessable; do not omit it from the lock to reduce multiplicity. Keep J and ineligible external baselines as separately labeled descriptive frontiers with actual available values.
3. Use only inner validation and pilot records for nomination. Document the registered screen or contingency that made a slot eligible, its delta/CMI budget, anchor-common settings, and any phase-I fallback status. A descriptive fallback cannot be relabeled as a feasible registered target.
4. Call `family_manifest(slots, alias_of=exact_Q_alias_map)` and store its complete endpoint objects and count in the lock. Each distinct slot–comparator pair contributes **10 endpoints**: five roles × U/PWGTP. A one-slot/four-distinct-comparator example gives `m=40`, two-sided Bonferroni `z=3.2272184259631627`; two such slots give `m=80`, `z=3.4205267011318305`. Compute the actual `m` from the lock rather than copying either example. Use identical bounds and signs for favorable and unfavorable results.
5. Store the separately assessed H capability clauses (`CE_candidate−CE_H≤−0.01` at development point estimate), the paired-household bootstrap seed/count, the common cross-anchor resampling rule, selection timestamp, and an `outer_assessment_opened=false` declaration. The H capability is not silently folded into the primary multiplicity family.

Commit the lock and verify its exact bytes/commit before the separate outer loader can return labels. The outer loader must verify the lock, original prepared-object SHA and requested anchor/role before returning only the registered attacker-validation rows; the normal sanitized loader continues to strip labels. Any corrected scorer after opening keeps the original lock and both scoring records. The 2018 outer set remains historically reused development evidence, never a new untouched confirmation year.
