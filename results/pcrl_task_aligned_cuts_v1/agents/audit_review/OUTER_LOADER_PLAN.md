# Lock-gated outer loader: implementation fixture plan

No outer rows or outcomes were opened to write this plan. The current default loader uses sanitized prepared copies and cannot score attacker_validation labels. A separate post-selection entry point is required.

Implement `load_locked_outer_token_pool(index, anchor, release_id, Q, lock_path, lock_commit)` in a separate owned module, called only after the coordinator records the committed `SELECTION_LOCK.json`. Its order of operations is part of the gate:

1. Require a full 40-hex Git commit and obtain the lock bytes at that exact commit with `git show <commit>:<worktree-relative-lock-path>`. Require byte equality with the on-disk lock. Reject an uncommitted lock, changed bytes, a lock path outside the study worktree, a lock whose recorded status is not `selection_frozen_before_outer`, or a lock with any `outer_opened`/assessment result field already set. Check that its protocol-lock SHA, input-index SHA, split SHA and generated endpoint-family SHA match current pinned bytes. A reporting commit made later is allowed only if it points back to the same exact lock blob.
2. Require `(anchor, release_id, Q file/array SHA)` to be an exact listed slot or comparator in that lock; aliases resolve to the canonical Q. Reject unregistered releases and mismatched token widths. The locked family must contain every five-role × two-weighting endpoint for every distinct selected slot/comparator; `inference.family_manifest` regenerates the list and count from locked names/aliases. Neither a test loss nor an outer attack selection may change it.
3. Only after those checks, verify the original archived prepared member SHA from `REUSABLE_INPUTS_PINNED.json` and deserialize it. The sanitized working copy has no true outer labels and is not used here. Extract only the `attacker_validation` fields needed for registered scoring: four H_A columns, two H_B columns, original-person IDs/households/weights, true same_residence/SEX/RAC1P labels in their original class schema, and the frozen T0 codes needed internally to form exact token probabilities. Do not return raw X, encoder objects, an individual code or Q row to predictor routes. The scorer receives only H, token-law and labels through the existing role-aware score API; public outputs remain aggregate.
4. Atomically write a private `ASSESSMENT_OPENING.json` with lock commit/blob SHA, original prepared member SHA, release/Q pins, anchor and UTC first opening. Subsequent technical rescores must use the same lock blob and retain the first opening receipt. A changed candidate, attacker slate, endpoint family or lock after this point is a new explicitly post hoc development stage, not a repaired confirmatory run.

Focused synthetic tests should reject a missing lock, working-tree-only lock, changed committed bytes, wrong protocol/family pin, unregistered Q, wrong anchor, malformed class schema and partial opening receipt. A positive toy test should commit a lock in a temporary Git repo, load a hash-pinned synthetic prepared member, expose only the declared score columns, and replay the unchanged lock on a second call without changing the opening timestamp. No actual 2018 outer rows are needed for these fixtures. The final loader cannot be exercised on real outer data until selected-panel fit/audit receipts and lock bytes are committed and verified.
