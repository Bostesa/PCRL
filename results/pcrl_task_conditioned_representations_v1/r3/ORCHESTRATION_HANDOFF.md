# Training and nomination orchestration

`build_training_units.py` is a metadata-only helper. It imports no numerical packages, opens no dataset archive, and never launches workers. Its `prepare` command binds the source manifest, science lock and ordered applicable amendments, translates the public recipe key `gradient_clip` to the trainer key `clip`, and prepares four utility and six calibration workers. Existing root-prepared utility `_READY.json` records can be imported without duplicating their jobs. Its `protect` command consumes the pinned completed six-normalization index and generates all 42 protection workers, sharing the JOINT constant exactly with LOCAL_TWIN, JOINT_UNCONDITIONAL and both sequential orders. LOCAL_CONDITIONAL and RAW use their separately registered constants. RAW warm state hashes remain pinned.

The actual private initial index, calibration-results index and protected-worker index were prepared without numerical execution by R3. All four utility fits and all six calibrations were executed by the coordinator's durable queue. The coordinator schedules the 42 protected workers from their immutable private specs. Generated metadata remains private and includes exact manifest/model paths; public code contains no identifying path literals.

`nomination_worker.py` runs only under an authenticated verification queue slot. The worker spec supplies pinned `manifest`, `science_lock`, and `fit_results` records (each `{path,sha256}`), plus fresh `private_output` and `public_output` destinations. Optional `family_strengths` must equal the locked nine-family ladders. All 46 private FIT result records and all four saved milestones per configuration are required. The worker verifies input/checkpoint hashes, per-encoder matched counts, and the full sequential selection definition before calling the held `select_common` implementation. It then forces the exact local twin at the chosen JOINT strength and epoch and freezes every family fallback from FIT alone.

The private draft contains canonical `instances` associations `{arm_id,seed,checkpoint_sha256,...}`, selected `nominees`, and diagnostic `fallbacks`. It records source aliases by exact encoder/head state comparison and retains each checkpoint's actual training-family provenance. The source reference uses the restored utility epoch-zero checkpoints. Fallback IDs are `<family>_DIAGNOSTIC_FALLBACK`. The selector's paired-seed sensitive sum and its half-valued mean are explicitly labeled; their ranking is identical.

The draft status is `FIT_SELECTED_AWAITING_R6`. This status cannot pass the INNER task-label guard. R6 independently replays source/weights/releases, every checkpoint's task and sensitive diagnostics, selection, sequential freeze and update accounting. Only the coordinator can use the reviewed draft to finalize the separate `FROZEN` nomination lock before INNER task labels open. Actual original point eligibility remains unevaluated in the FIT draft.

All core training/model/selection source hashes remain held. Adding orchestration helpers does not change the locked objective, optimizer, strength ladder, checkpoint opportunity or scientific criteria. No R3 subprocess ran a numerical worker.
