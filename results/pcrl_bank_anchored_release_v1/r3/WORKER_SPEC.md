# Queued R3 utility unit

Run only after R0 seals the effective campaign and registers the unit with the global queue. The executable is `python3 -m bank_anchored.r3_worker --config ABSOLUTE_PRIVATE_CONFIG.json`. It calls the queue's active-child guard with stage `protection` before opening any role archive. Numerical descendants must use the host's fixed thread limits and the one shared queue slot. R3 has performed **no** real FIT or INNER scoring while this specification is prefit.

Each private config has exact keys `schema,unit_id,stage,role,arm,seed,seal,role_manifest,public_table,bank_receipt,bank_wire,r5_source_replay,law,outputs`. The schema is `pcrl-bank-r3-utility-job-v1`; role is `OSF_DEFENSE_FIT` or `INNER_SELECTION`; seed is 0 or 1; arm is one of the eight new fixed-arm IDs. `stage` is exactly `protection`. Each input is `{path,sha256}` and must appear byte-for-byte in the active queue source list. Outputs name a new R3 public CSV, R3 owner-only per-person vector NPZ and R3 public receipt. The queue source list must also pin both R3 Python files and the role-only `income`, `occupation`, `references_s{seed}` archives. The source R5 `BANK_OLD_POINT_AUDIT.json` must report W_TSTAR 24/24 historical point clauses and PASS. The R1 W_TSTAR receipt binds the seed, selected source model, exact role rows/groups, table, policy, decoder and private saved wire.

The R2 law archive must contain **only** `row_id,unit,code_r1,code_r2,mass,valid,b0_code_r1,b0_code_r2`; dimensions are rows × 16 for actions, with float64 normalized mass, bool validity, zero mass on invalid slots, int64 global bank IDs, and exact admitted row order/group IDs. The saved R1 B0 role wire must contain only `row_id,unit,code0,prob0,decision0,code1,prob1,decision1`. R3 compares R2's B0 IDs with its ten little-endian public bits, then verifies every saved B0 probability and decision by decoding the frozen W_TSTAR public table. The worker rejects missing or extra NPZ members, including a sensitive-label field. It does not load SEX.

For each role/arm/seed, the output CSV has 18 signed aggregate rows: 2 tasks × 3 metrics × `B0,U0,Ucal`. On FIT, only the six B0-relative rows are the new optimization-proxy gate; U0/Ucal rows are explicitly old-reference diagnostics. On INNER, the 12 U0/Ucal rows are the original point-eligibility gate; B0 rows are diagnostics. Margin is candidate minus reference for accuracy and both losses; accuracy passes if margin is at or above the negative cap, while NLL/Brier pass if at or below their positive caps. Source people, IDs, labels, fitted policy arrays, sampled coins and individual costs stay private. The private vector NPZ holds paired row/group IDs and task/reference metric costs for later duplicate-group inference; its SHA appears publicly but its values do not.

The worker emits no privacy score, no candidate nomination and no confidence PASS claim. R0 aggregates its unit receipts and writes shared gate/decision files; R5 independently recomputes the endpoints without importing R3 code.
