# R1 deployment and campaign custody plan

This is a prospective plan. No snapshot or restore has run. The frozen
strongest-control lock selects V_S21 under the declared rule. The custody
source map and plan bind that lock and the earlier V_L nomination lock.
R5 must audit the exact source-hash plan before R0 seals the custody stage.

The versioned owner-only snapshot will preserve the frozen raw83 P0 teacher,
heads, router, H-CLASS decoder and original-ID public banks for both seeds.
It will include the P0, V_L nominee, V_J diagnostic and strongest-control
FIT code releases for all three declared realizations, along with the
permitted 32-row raw83 sample and sealed HMAC stream roots. P0's three
realizations are exact deterministic aliases.

It will also copy every admitted campaign-private R1–R5 artifact opaquely:
fitted policies, checkpoints, role-scoped laws/releases, R3 cost and
recovery vectors, fresh R4 frozen readers and their predictions/views,
control probes, and verification outputs. R1's custody tools only stat,
hash and copy these bytes; they never deserialize private arrays or use
task or SEX labels for science. The inventory includes representative
new R4 reader receipts for P0, V_L, V_J and the strongest control, both
seeds. The historical frozen P* H2 reader is preserved separately.
Completed immutable R0 queue unit logs and receipts are copied too. Live
queue state, occupancy and slot locks are excluded; end-of-study state
requires a separate read-only closeout receipt.

The scientific source tree contains the complete transitive Python
imports for deployment and reader replay, including lazy decoder modules.
A Git bundle preserves the exact committed research branch. The historical
all-role teacher release, old assessment and HEAD files are excluded.
Public indexes contain aliases, sizes and hashes without identifying local
source paths. Private source maps and snapshots remain owner-only.

After a prospective custody amendment, R1 will make a write-once versioned
same-device snapshot and a restore using snapshot bytes only. Source,
snapshot and restore SHA-256 checks use uncached reads. A separate queued
numerical replay will run restored raw83 release CLIs and representative
historical and newly fitted readers; R5 will independently replay those
checks. A copied private archive is byte-integrity custody, not fresh data
admission or independent scientific confirmation. Failed attempts remain
preserved. Off-device custody stays pending while the external drive is
absent.
