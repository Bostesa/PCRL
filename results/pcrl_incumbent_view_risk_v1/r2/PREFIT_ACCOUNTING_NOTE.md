# R2 prefit activity accounting and lock bridge

The V4 scientific fixtures passed before any R2 real-data fit. This
prospective engineering amendment adds counters without changing any release
law, objective, reader fit, utility cap, safety margin, candidate ranking, or
frozen sampling root. It supersedes the earlier R2 source index, which remains
preserved for audit.

Every R2 unit receipt now reports exact FIT reader family-fold fits, retained
reader objects and loss positions; NumPy and Torch policy forward calls, rows
and action positions; optimizer and factor updates; role input and FIT label
file reads; group-fold assignments, support preparation and task-cost matrix
builds; and cached role release packages and rows. The counters measure work
performed in that unit, including incomplete work. Source-space, policy and
training counters reset once after all file pins are checked and before any
role array is opened. The reader counts exclude stage-marker metadata.

The original queue ADMISSION_LOCK remains the active environment seal. The
CAMPAIGN_LOCK binds the scientific recipe and must be registered among
protection-stage amendments. A later engineering amendment, if any, must be
the latest protection amendment and match both the config and queued spec.
Public scientific result and policy receipts bind CAMPAIGN_LOCK; the unit
receipt also records the admission seal separately.

The separate three-test accounting fixture checks numerical identity under
instrumentation, exact counter increments and this two-lock relationship. It
must run under the shared queue after R0 registers a dated engineering
amendment. No real-data fit is admitted by this note alone.
