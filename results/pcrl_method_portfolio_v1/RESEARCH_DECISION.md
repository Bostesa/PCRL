## Work completed

Twenty native reasoning agents, including S1, were live at peak: four shared roles and four roles in each of four teams. Each team produced a hypothesis, primary prior review, method specification, strong controls, failure tests, exact provisional units, a skeptical review and code under an isolated local research worktree. S4 was independent of implementations. S1 integrated the local commits into the coordinator branch. This did not create twenty training slots: S3 enforced a two-heavy-process machine budget.

The designs differ in what they change. A changes a frozen score channel and discloses a sampled code/probability, not its private input bin. B retrains stochastic raw-input bottlenecks and heads. C selects global grouped raw inputs and discloses the selected values. D repairs frozen latents by a many-to-one hard code; its revised privacy objective reads public code IDs, after review found that decoded-centroid similarity could improve with unchanged revealing IDs. A is score-only. B, C and D are feature-track candidates. Their metrics cannot be pooled across these interfaces.

No Adult screen ran. S2 proved the inherited loader transiently reads assessment labels before masking and found no verified role-only feature-and-label export. The new guard has zero admitted real files by design. A score-only cache lacks labels. S3 found two other active Python processes of unverified heaviness and reserved both global slots; no campaign heavy unit ran. GitHub DNS prevented pushes and remote pin verification. The blocking `CAMPAIGN_LOCK.json` was not an effective pre-fit lock. The old assessment and HEAD_VALIDATION labels were not opened for this portfolio. ## Premise and novelty decisions

- **A:** valid score-channel question under original mean limits; old ACS Q already fitted a stochastic finite channel. This is a transfer/benchmark, not algorithmic novelty. The task-only rate-distortion stochastic arm replaced a weaker entropy control before results.
- **B:** end-to-end stochastic bottleneck changes acquisition and is distinct from the old raw adversarial penalty. VIB and privacy-funnel objectives are established; the KL rate term does not bound SEX AUC. Sampling benefit needs the deterministic, task-only, separate, sequential and raw-joint controls.
- **C:** if raw selected values are disclosed, ideal coalition information is the raw union. Head calibration cannot erase it. The relationship exclusion and additive selector are simple, testable ideas; unrestricted matched-budget controls and raw-union attacks are mandatory. A useful result could remain a standard feature-selection baseline.
- **D:** prefit review killed an overlarge 32-bit product code and a decoded-vector privacy objective that could ignore disclosed IDs. The revised 10-bit hard-ID objective is a coherent heuristic, with no certificate. Capacity-matched task-only VQ is present, but realized-distortion matching is absent, so privacy-objective and joint attribution are unavailable even if a future result looks favourable.
