## Inputs and deployment

Let frozen purpose encoders produce separate 16-dimensional task-trained latent vectors `h1(x)` and `h2(x)` from the 83 permitted columns. The historical JCV source at `568f970683d11373d717ca112b619fbdde40d0b3` (`jcv/train.py`, `METHOD_CARD.md`) documents separate 64-64-16 task encoders. The intended tensor is exactly `Model.encode(i, X) = model.enc[i](X)` before any `maps[i]` erasure, source task head, or calibration. S2 matched all three local hcal U checkpoint hashes to its public manifest, and S4 admitted role-only files with ordered 83-column schema hash `7101f2fb37b623a08221c32b33eedf132cf0c4c376bb4042ab9cf16da08ad975`; a D-specific tensor/83-column preprocessing parity receipt still requires the effective S1 lock and S3 queue. No Adult tensor has been forwarded for D. The two latent bases are not known to align. On OSF_DEFENSE_FIT only, estimate each purpose's per-coordinate mean and population standard deviation (`ddof=0`), with a fixed `1e-6` floor on the scale; all arms use these same public normalization constants. No Procrustes, protected-label routing, or person-specific mask is used.

Each party computes only its own standardized `h_i(x)`. One *shared* codebook `C` has 1,024 centroids in 16 dimensions. The fitted and deployed PyTorch path computes squared Euclidean distances in float32 and chooses the lowest index on an exact tie. One index (10 bits) selects a decoded 16-vector **in the shared standardized coordinates**; there is no inverse-normalization. The same `C` is used for both purposes. Both heads consume these selected centroid vectors; the local and pair privacy terms consume hard **code IDs** as specified below. The two purpose heads each use `Linear(16,64)`, exact GELU, `Linear(64,n_classes)`, then softmax. All head outputs depend solely on the hard decoded code. No raw `h_i`, teacher scores, pre-quantization residual, or original clean head output is sent. There is no raw-score fallback: every finite input obtains a code. Nonfinite inputs are a deployment error, not a hidden refusal or release of raw values.

The recipient view includes the index, equivalent centroid vector, calibrated probabilities, decision, task identity, and any error/length/flag metadata. Public model weights, codebooks, scalers and decoder tables are attacker side information. The coalition receives the aligned pair of complete recipient views. When all flags are constant and the head/calibrator depend only on the code, the full view and the code ID generate the same information for an ideal reader: `I(SEX;V_i)=I(SEX;ID_i)` and `I(SEX;V_1,V_2)=I(SEX;ID_1,ID_2)` for that fixed release law. This equality is structural only under the stated wire contract; a varying flag or fallback breaks it. Practical attacks still see all transmitted fields. Permitted demographic side information must be frozen centrally. A fixed single release per person is the default query contract. No private per-person input from the other provider is needed at inference.

The scored wire has exactly `code_ids`, `decoded`, calibrated `probabilities`, `decision`, and scalar `metadata`. Each metadata scalar, including purpose, code length, block count, fallback, stochastic marker, arm identity, calibration family and calibrator SHA, is preserved as a literal public constant in S2's attack view; the per-person arrays are bound to named nonoverlapping columns. Hard IDs are additionally expanded into categorical one-hot and ten-bit inputs for learned readers, with direct ID/pair-ID cell keys for specialist readers. The release validator rejects row-varying metadata under this fixed contract. S4 must independently reconstruct the decoded vector and calibrated head output from the sealed codebook, head and calibrator; parity between two Team D view builders alone is insufficient.

**Fixed-ID counterexample.** In one dimension, let SEX groups occupy `h=-1` and `h=+1`. With centroids `c0=-epsilon`, `c1=+epsilon` for any `epsilon>0`, nearest-centroid IDs remain 0 and 1 and reveal SEX perfectly. The decoded vectors converge as `epsilon→0`, so a Gaussian MMD on decoded vectors can approach zero without any ID privacy gain. This is why the protected objective below operates on public IDs and why hard-ID attack recovery remains the endpoint.

## Fitting objective and finite capacity

Fit on OSF_DEFENSE_FIT only, conditional on a lawful S2 export. Initialize the shared codebook by seeded pooled 1,024-cluster k-means on both standardized purpose latents (`n_init=1`, `max_iter=100`, `tol=1e-4`, Lloyd algorithm, `random_state` equal to the paired model seed). Use the same source encoders, normalization and initialization recipe for D and the task-only quantization ablation. The forward pass selects the hard nearest centroid. For training, define hard one-hot assignment `H_i`, float32 distance softmax `A_i = softmax(-||h_i-c_k||² / 1.0)`, and `Y_i = H_i + A_i - stop_gradient(A_i)`. PyTorch's row-stabilized softmax is used without a second temperature. Thus **forward values are exactly hard IDs** while backward gradients pass through the distance softmax to codebook locations. The decoded feature is `z_i=Y_i C`; task and reconstruction gradients reach selected centroids directly and all centroids through the assignment surrogate. The code-identity dependence term below reaches centroids only through that surrogate. Only the task loss updates head weights. Source encoders and normalization constants are frozen. No soft code is released or scored. Optimize the shared codebook and two heads for 20 complete epochs, batch 256, Adam learning rate `0.001`, fixed final iterate; no performance-based epoch choice. Set numerical library threads to one. Random seed identifiers are S1's paired screen seeds. Tiny checks must show nonzero task and dependence gradients into `C`, and that the latter can actually alter hard assignments on a predeclared fixture.

For a fitting person `j`, let `q_i(j)` be the head probability from the hard decoded code and `u_i(j)` the frozen Ucal teacher probability used only as a training target. D's protected task objective is the mean over two tasks of observed-label cross-entropy plus `0.5 * KL(u_i || q_i)` plus `0.25 * ||h_i^{standardized} - c_{code_i}||²/16` centroid reconstruction loss. This last term updates the selected centroid, not the frozen encoder; calling it a VQ-VAE commitment term would misstate its gradient. Task labels, teacher probabilities and SEX are fitting-only; none are deployment inputs. The exact task-only ablation uses the same `0.25` coefficient and architecture. The separate bounded task/distortion matching controls use reconstruction coefficients `{0, 0.25, 1}` on otherwise identical 1,024-code task-only fits; `0.25` is an exact alias of the ablation. These are controls, not additional D method prototypes, and every setting is retained and charged. Task-only fit objects must omit SEX labels entirely, and the trainer rejects a task-only fit object that supplies them.

**Prefit task and distortion match.** After every arm receives S2's fixed held-out calibration, measure on `CALIBRATION_HELDOUT` the absolute difference from protected D in each purpose's accuracy, natural-log NLL and sum-over-classes Brier. The respective inclusive tolerances are `0.002`, `0.002` nat and `0.001`. Also require each purpose's mean squared reconstruction error in its own standardized latent coordinates to differ from protected D by at most `0.10 * max(D_MSE, 1e-6)`. Only controls satisfying all eight gaps are eligible. Among eligible controls choose the one minimizing the maximum of the six utility gaps divided by their respective tolerances; break an exact tie by smaller reconstruction coefficient. If none is eligible, record `NO_MATCH`; do not promote the nearest miss into a matched control. This selection reads task labels and latent distortion on the authorized calibration role, never SEX labels or recovery, and its reuse of calibration rows for temperature fitting is disclosed. Freeze the selected coefficient and recheck all eight gaps on `INNER_SELECTION` without reselection. All three task-only controls receive fresh complete-view attacks and remain in the results regardless of eligibility. A failed inner recheck prevents a task-and-distortion-matched compression or joint-component attribution; it does not erase those reported arms or alter the common utility/privacy endpoint rules.

For D's protected fit add `1.0 * (MMD_1^2 + MMD_2^2 + MMD_pair^2)/3`, comparing SEX-conditioned distributions of the **hard public code IDs** and aligned code-ID pairs. Draw each minibatch **once over aligned people** and compute both purpose codes for those same row IDs, preserving the inherited group and seed pairing. Never sample the two purpose batches independently: that would destroy the coalition clue the joint term claims to target. Local code features are the exact 1,024-coordinate hard one-hot `Y_i`; therefore each local squared discrepancy is exactly the squared Euclidean distance between that minibatch's SEX-conditional empirical code-frequency vectors in the forward pass. For the up-to-2^20 pair space, fix two independent Rademacher sign tables `Phi_pair1`, `Phi_pair2`, each `1024 x 128` with entries `±1/sqrt(128)`. Generate them in that order in float32 from one CPU `torch.Generator` initialized with `manual_seed(2*paired_model_seed+1)`, using `torch.randint(0,2,(1024,128))` and mapping bits to signs. Pair features are `sqrt(128) * (Y_1 Phi_pair1) elementwise_times (Y_2 Phi_pair2)`. Their forward values depend on paired code **identities**, not centroid coordinates, and approximate a delta kernel on that finite pair space. Each squared discrepancy is the nonnegative squared norm of the difference between the two SEX-group mean features in that minibatch. A batch lacking either SEX group is invalid and recorded. The *biased* minibatch squared difference has positive null expectation even when SEX and code are independent (approximately `1/n_0+1/n_1` for diffuse local codes); it can reward generic collapse. The 128-feature pair sketch also has a large nullspace: its loss can be zero while SEX-conditional pair-ID laws differ. Thus this is a training heuristic, not an exact pair-information objective, attack AUC bound, or privacy certificate. Shuffled-SEX training and matched task/distortion compression are required controls. The joint term couples the two parties during fit while each deployment map remains local. Moving decoded centroids while leaving hard IDs unchanged does not improve this forward privacy loss; direct code-ID and pair-ID attacks decide whether any real privacy gain occurred.

Only one protected design and its task-only VQ ablation are D prototypes. The coefficients, code size, architecture, epochs and kernel are fixed here as a pre-lock proposal; S1 must either bind them in CAMPAIGN_LOCK.json or record a pre-fit revision. No coefficient/capacity sweep follows outcomes.

The prefit rule above identifies a capacity-, task- and distortion-matched member only if one actually meets its tolerances; the `0.25` shared reconstruction coefficient alone does not establish that match. No similar-looking arm is an alias without exact hashes for split, seed, source, columns, preprocessing, architecture, calibration, output and fit budget.
