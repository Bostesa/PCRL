## Comparison contract

Every new arm starts from the same frozen task-score source, row order, predicted-class rule, fixed input discretization, and fixed public output bank. The proposed input has 32 income and 128 occupation fine score bins per predicted class. The proposed output bank is the pinned hcal FINE-TASK `i8o64` token bank with H-GLOBAL-TEMP vectors, at most 8 income and 64 occupation tokens per predicted class. Source admission must record the **actual** classwise cardinalities; these numbers are caps, not asserted observed counts. Each recipient sees its sampled probability vector, predicted decision, code identity, and every transmitted flag or fallback value. A coalition sees both aligned releases. The public channel matrices, output bank, calibration and source model are available to a defense-aware reader. Only the provider holds private per-person inputs; neither recipient or attacker is given unreleased provider inputs merely because a public model could process them.

Use one draw per person under the frozen seed/counter sampling plan. Train and evaluate on that actual draw. Exact expectation over the fitted finite law is an optimization receipt, not a reported held-out loss or an uncertainty bound. Preserve each recipient's predicted class by restricting its output bank to the input's class. Releasing the decision alone is the information floor for an ideal reader, but it is eligible as a utility comparator only if it passes both mean-loss reference gates.

The proposed law has two **local** channel matrices `Q_r(z_r | t_r)`, with independent per-recipient draws conditional on the fine bins. Its joint objective minimizes a normalized epigraph of exact fitted-law SEX Bayes classification accuracies for recipient 1, recipient 2 and coalition, relative to each view's decision-only floor and fine-bin reference. Alternating SciPy linear programs solve conditional subproblems; this gives no global optimum certificate. The control bank must include the following distinct constructions, with identical class restrictions, bank, discretization, allowed labels, capacity, calibration treatment, starts or restart count, optimization tolerance, and total compute ceiling where relevant:

Each task-only fit worker receives a separate `TaskOnlyLaw` with only its own authorized fitting marginal `p(T_r,Y_r)`, fixed recipient bank/classes and task-reference caps. It receives neither the SEX-bearing law/FIT SEX file nor the other recipient's private per-person bins and labels. The custodian constructs each marginal from approved role-specific task inputs; a true SEX array materialized and later ignored would not meet this control contract.

### Adult deterministic ablation rule, before outcomes

The fixed start order is `TASK-DET`, rounded `LOCAL-STOCH`, rounded `SEQ-12`, rounded `SEQ-21`, rounded `JOINT-STOCH`. Both sequential orders are separate starts even if their matrices later alias. For each stochastic start, choose each row's largest channel probability within its predicted class, breaking ties by lowest output bank ID. All five starts and any duplicate identities are recorded. No start may read an Adult outcome when chosen.

First repair each rounded start against the **fitted** NLL and Brier caps using task-label costs only, never SEX. The matched TASK-DET solution is the predeclared feasible anchor. Replace differing rows with their TASK-DET assignment, ordered by the largest reduction in `ΔNLL/0.010 + ΔBrier/0.005` (ties by input-bin ID), until both caps pass; the final all-anchor state is guaranteed feasible if TASK-DET passed. Record every change and utility trace. If TASK-DET is infeasible or incomplete, this repair and its dependent deterministic comparison are incomplete. For unseen input bins, use the lowest fixed same-class output ID in all controls; count that ID in the deployable code set.

Then make at most five full alternating sweeps in recipient order 1 then 2, iterating input bins by fixed ID. For each bin, consider every other same-class output ID under the exact pre-outcome **anchored lexicographic rule in METHOD_SPEC §2**: priority tuple `(normalized maximum a, pair Bayes accuracy, summed local Bayes accuracy, fitted NLL+Brier, output ID)`, face tolerance `ε=1e-10`, and best-so-far face anchors. The first numeric priority decrease greater than `ε` qualifies and resets lower-priority anchors; `δ=1e-9` labels a material improvement in the receipt but is not an acceptance threshold. A flat-face move cannot exceed any higher-priority current-face best plus `ε`. Among qualifying moves choose the exact smallest tuple, retaining lower ID only for numeric ties. Reject a visited full assignment, log candidate and anchor before/after, update exact finite-law sufficient statistics and require full objective/utility sweep replay residual at most `1e-10` on the synthetic check. Stop at the **same total process-CPU ceiling** as JOINT-STOCH, to be fixed from S3's prelock smoke receipt; check the CPU slice after each replay as well as during repair/search, and record separate HiGHS wall-clock limits. Retain all partial starts and stop reasons as diagnostics, but select a channel only from completed feasible starts. If any required start is incomplete, suppress the selected channel and classify the whole comparison incomplete. Tiny-law MILP is an oracle for the restricted tiny instance only. A stochastic win over this bounded heuristic is evidence against this control, not proof that no deterministic channel can match it.

### Adult task-only deterministic compression rule, before outcomes

For **each recipient separately**, the source hcal `FINE-TASK` fine-bin→token assignment is start 1 **only if** exact input-bin, output-bank and calibration IDs match Team A's admitted bank. Start 2 rounds every TASK-RD row to its largest same-class probability, with the lowest bank ID on ties. These starts are declared before SEX recovery is inspected. The task-only worker receives only `p(T_r,Y_r)` and task-reference caps, never true SEX counts or the other recipient's per-person information. On identical OSF_DEFENSE_FIT rows with the same class order, clipping and weights, each fitted cap is `min(cost(U0), cost(Ucal)) + allowance` (`0.010` NLL or `0.005` summed multiclass Brier). A start is feasible if that recipient's fitted NLL/Brier caps against both frozen references pass. Choose the first feasible start in the fixed order as a repair anchor. If neither is feasible or source map identity fails, TASK-DET is **incomplete**; do not call a weaker task-only arm the strongest comparator.

For an infeasible rounded start, replace each row differing from the feasible anchor by its anchor bank ID, ordering rows by largest reduction in `NLL/0.010 + Brier/0.005` under the task-only marginal (ties by input-bin ID). Stop when that recipient's NLL and Brier caps pass against both references; replacing all rows reaches the anchor, so a feasible anchor guarantees repair. An initially infeasible rounded start counts as completed **only after** this exact repair reaches both caps and the subsequent bounded search terminates normally. Record every replacement and the full utility trace. For zero-mass bins use the lowest same-class bank ID and count it in deployable capacity.

From each feasible repaired start, perform one fixed-order headroom pass over input bins: among **currently active same-class IDs**, reassign a row only if it strictly reduces `NLL/0.010 + Brier/0.005` and keeps both caps for that recipient; ties choose the lowest ID. Then repeatedly test each active code ID for elimination. Its rows are independently assigned to the remaining active same-class ID with lowest normalized task loss (ties by target ID). A removal is admissible only when both caps hold after **all** affected rows are reassigned. Apply the admissible removal with the smallest increase in normalized task loss (ties by removed ID), then run one more headroom pass; stop when no removal is admissible or the sealed CPU ceiling is reached. Keep the code count, fitted utility and every attempted removal in the receipt. Select the completed start with fewest activated deployable IDs, then lower unnormalized fitted `NLL + summed multiclass Brier`, then the fixed start order. Each start receives half of a total TASK-DET CPU ceiling fixed from S3 smoke; check the deadline after final utility replay. If either required start reaches the ceiling, retain its best result only as a diagnostic and suppress the selected channel for the incomplete TASK-DET comparison. This is a bounded task-only heuristic, not a global compression optimum. The tiny-law activated-code MILP remains a correctness oracle and has a separate `NLL + Brier` tie stage; failure of that stage is also incomplete.

## Strongest-control rule proposed to S1/S2

First reject arms with invalid premises or incomplete controls, then determine point utility eligibility on **both** tasks against **both** U0 and Ucal using the common protocol's accuracy, NLL, Brier and retention rules. Among eligible noncandidate score arms, choose the arm with the lowest aligned-coalition AUC from the same frozen fresh-reader slate, without using finalist outcomes to revise the pool. Ties within the registered numerical tolerance use the smaller worst-task normalized NLL/Brier excess, then simpler interface, then fixed ID order. A privacy improvement is `AUC(strongest control) − AUC(candidate)`; local shifts are candidate minus that same control, with supplementary comparisons to all controls. Select one logical arm across paired seeds, never the best seed or random draw. S1/S2 must lock the final comparator selection and simultaneous inference conventions.

For **joint-design** credit, additionally compare the candidate against the better of both sequential orders and the strongest eligible non-joint arm under the exact Team A interface. A stochastic candidate tying the deterministic control has no randomness increment. A candidate tying local or sequential controls has no joint increment, even if it beats older T*.

## Complete-view attack slate

Fit new SEX readers only on `ATTACK_FIT_NEW`; screen on `INNER_SELECTION` as S2 locks. Include linear and nonlinear score readers, categorical code/cell and pair readers, defense-aware readers using public channel and decoder tables, both ignore-other-recipient coalition readers, and readers of decision, output probability, input/output token identities **only if transmitted**, code length, flags, mask and fallback. Integer token IDs are categorical, not continuous magnitudes. A raw-score or original fine-token reader is a legitimate attack only if that value is transmitted or inferable from transmitted information. Fit equal attacker capability per arm, select by the fixed inner rule, and report all local and pair views even when the selected reader ignores one recipient. Do not replace a sampled vector by its conditional mean in the view.

The pinned hcal complete-interface common bank (LR×5, MLP×4, HGB×4, DA_LR, DA_MLP; cell/pair readers; ignore-other readers) is the historical coverage floor where its original view composes into a candidate's actual interface. It cannot be treated as a new arm's full audit when its tokens or probabilities differ. Fresh new-arm readers must be fitted. Public lookup tables do not themselves reveal private per-person source scores.

## Matching and accounting

An arm is an immutable identity: source SHA; source checkpoint; two seed IDs; role split and groups; 83 columns and preprocessing; input discretization; output bank and decoder; class constraints; channel architecture; utility/calibration law; optimizer code and budget; release sampling plan; complete view. Two arms are aliases only after exact identity or bitwise equality of transmitted views on every permitted check row; near-equal metrics are not aliases. Cache immutable old predictions read-only. Charge every channel optimization, calibration, attacker fit, source forward pass, preprocessing pass, sampled evaluation pass, and independent numerical replay to the shared queue. A skipped or aliased unit remains in the registry with its reason and zero actual run count.
