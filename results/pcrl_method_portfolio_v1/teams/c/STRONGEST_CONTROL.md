# Team C: strongest matched controls (pre-lock design)

## Scope and interface

Team C is a FEATURE-track method. The pinned Adult input has 83 permitted encoded columns from ten named source fields. Every categorical field is an indivisible one-hot block. `education` and `education-num` represent the same raw fact and are tied, yielding **nine toggleable atoms**. Count both atom count and transmitted encoded-column count. The input excludes SEX, race, income, occupation, fnlwgt, row identifiers and task labels. The mask is global per purpose and publicly known; SEX is available during mask fitting only.

Recipient 1 receives its selected **raw normalized numeric values and full one-hot blocks**, its task probability vector and decision, mask identity, head identity and all transmitted flags. Recipient 2 receives the analogous occupation view. The coalition receives both aligned views, so its raw input is the union of both masks plus both heads' complete outputs and metadata. The all-zero unseen-category convention must be preserved. A feature-view result cannot be compared as though it were a score-only result. The deterministic task head supplies no new *ideal* information once its raw inputs and public weights are known, but finite attackers still receive both outputs in the scored view. An original clean teacher output must not be appended.

`relationship` is a known shortcut: the pinned JCV admission reports Husband/Wife almost determines SEX for roughly 46% of rows. The candidate proposes excluding it in both masks before selection. This is a **premise**, not a learned discovery. We therefore include a simple retrained `DROP_REL` control, and any additional claim for selection must beat it. The full-feature control retains it. Restricted attribution controls share the candidate's relationship-excluded universe. **Unrestricted matched-budget controls may select relationship** and are needed to establish the strongest task-only and non-joint comparison. We report local and union relationship retention for every arm.

## Budget rule

Freeze the **capacity-matching rule** before fitting. For each seed, the candidate's fitting-role selector realizes `b = (k_income, k_occupation, k_union)` in nine semantic atoms; the controls then match this vector without consulting INNER_SELECTION labels. A controlled mask must meet the same recipient counts and, when combinatorially attainable without using coalition labels in an independent control, the same union count. If an objective returns fewer atoms, complete it by its predeclared objective/rank rule. If a control cannot attain the vector, identify its closest attainable point and label the comparison **capacity-mismatched**; it cannot support a joint-design advantage. A shared mask has `k_income = k_occupation = k_union`, so it generally cannot match distinct purpose masks. The registered `C-COMMON-MASK` targets the candidate union removal count when feasible, with any recipient capacity difference explicit. If infeasible, report its native feasible point and the mismatch. This one registered arm does not establish a second shared-mask point. Also report raw transmitted column counts because a 41-column native-country block and a one-column numeric field are not equal communication costs. Match the encoded-column vector when attainable; otherwise report that mismatch and avoid a capacity-equal novelty claim.

Every selector uses the same permitted fitting rows, frozen preprocessing, grouped atoms, deterministic seed order, task-head family, training/early-stop ceiling, calibration family, utility limits, attack budget and candidate evaluation count where the objective permits. Selection labels are restricted to OSF_DEFENSE_FIT. Calibration uses CALIBRATION_HELDOUT task labels under S2's common rule. Fresh attacker fitting uses ATTACK_FIT_NEW SEX labels; INNER_SELECTION is for evaluation. HEAD_VALIDATION and old assessment labels are inaccessible. Exact identity aliases require matching hashes of masks, training inputs, initialization, learned weights, calibrator, output view and budget; a similar AUC is not an alias.

## Registered arms

| ID | Control or candidate | Required comparison |
|---|---|---|
| `C-JOINT-GROUP` | Purpose-specific grouped masks chosen with local plus coalition SEX proxy and task utility | Candidate, one fixed selector design |
| `C-FULL-FEATURE` | Both retrained task heads on all nine atoms | Raw-input utility and leakage reference; not capacity matched |
| `C-DROP-RELATIONSHIP` | Both heads retrained after dropping relationship, no further selection | Tests whether the known shortcut removal alone explains any gain; capacity mismatch reported |
| `C-TASK-ONLY-REL0` | Two purpose-specific masks selected for task utility only after the same fixed relationship removal, at the same recipient budgets | Attribution control for privacy scoring beyond the fixed removal |
| `C-TASK-ONLY-ALL` | Utility-only masks at the same recipient budgets with all nine atoms available, including relationship | Strongest matched-budget task-only compression control |
| `C-INDEP-GROUP` | Two privacy-aware masks optimized independently after the same fixed relationship removal; the union is attacked | Structural ablation for pair-aware selection |
| `C-INDEP-ALL` | Independent privacy-aware selectors with all nine atoms available; their union is attacked | Strongest independent non-joint control at recipient budgets |
| `C-SEQ-INCOME-FIRST` | Select income mask first, then occupation mask conditioned on income mask and union recovery | Faithful sequential order 1→2, same search/fit budget |
| `C-SEQ-OCCUPATION-FIRST` | Reverse conditional order | Faithful sequential order 2→1 |
| `C-COMMON-MASK` | One common mask chosen to protect both tasks and SEX, then two retrained heads | Shared-mask removal control, with capacity caveat above |
| `C-PRIOR-COALITION-SELECTOR` | A faithful published coalition-aware grouped selector only if a compatible implementation is identified before lock | Otherwise `SKIPPED_NO_COMPATIBLE_PRIOR_IMPLEMENTATION`; a shared or task-only mask is not an alias of a paper's algorithm |

For the **matched competitive threshold**, use the utility-eligible controls with the same disclosure contract and attainable recipient/union capacity vector: `C-TASK-ONLY-REL0`, `C-TASK-ONLY-ALL`, `C-INDEP-GROUP`, `C-INDEP-ALL`, and both sequential orders. A faithfully implemented `C-PRIOR-COALITION-SELECTOR` would enter if registered before lock; a skipped slot cannot. `C-COMMON-MASK` enters only at a capacity point it can exactly match. Among these, the strongest privacy control has the **lowest** complete-view coalition SEX AUC; ties use the fixed arm ID order. S1/S2 own the campaign's exact strongest-control rule and uncertainty convention. Separately report the lowest eligible AUC over **all** feature-track controls, including unmatched `C-FULL-FEATURE`, `C-DROP-RELATIONSHIP` and shared-mask points. An advantage that depends on omitting a stronger unmatched control is described as capacity-specific, not a broad method win. A control that is not utility eligible remains on the frontier but cannot set an eligible privacy threshold. `C-DROP-RELATIONSHIP` is a required attribution comparison even when its capacity differs. We also show direct pairwise contrasts against both sequential orders, task-only compression and the best non-joint control. A feature budget advantage is never counted as evidence for joint design.

## Attack comparisons

For every arm and seed, fit the same fresh linear and nonlinear readers on (a) recipient 1 raw features + output + metadata, (b) recipient 2, and (c) aligned coalition union + both outputs + metadata. The coalition slate also includes attacks that ignore one recipient, raw-feature-only readers, and defense-aware readers of public masks/weights. A feature-only reader is essential because outputs may hide leakage already present in raw values. Null/constant, shuffled SEX, and a planted leak on a separate engineering copy check the pipeline. Masks are global, so a mask identity alone carries no per-person SEX information within an arm, but the reader still knows the mask. If a mask retains `relationship`, separately report its Husband/Wife conditional recovery and the affected fraction; never suppress those rows.

## Attribution

`C-JOINT-GROUP` beating `C-FULL-FEATURE` alone is insufficient. If either task-only arm, `C-DROP-RELATIONSHIP`, either independent arm, `C-COMMON-MASK`, a compatible prior control, or either sequential order explains the complete-view result at comparable utility and capacity, report the simpler method. Selection of fewer raw facts is a useful empirical result but not by itself a novel algorithm. No method can remove SEX information already disclosed by its selected raw features; a weaker fitted attacker is not a guarantee.
