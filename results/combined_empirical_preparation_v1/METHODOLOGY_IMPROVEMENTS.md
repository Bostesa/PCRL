## 1. Name every attacker by the access it actually has

**Problem**

- **The informed tier is described as something it is not.** The durable-guarantees "Tier 2"
  ("informed") attacker is a Gaussian likelihood-ratio test. It is fit on the *pre-noise*
  representations of a labelled training population, plus the exact noise covariance, and scores
  **one** noised release per target (`dg:utils/battery.py:60-103`) [verified, IC-F5, DG-F01].
  - It never receives the target's clean vector, so it is not an insider.
  - It never averages repeated releases, so it is not repeated-query.
  - The README (`dg:README.md:46-49,62-66`) and the paper (`paper.tex:251-254`) say otherwise.
- **The tier is undefined for most baselines.** Against deterministic baselines the LRT is QDA on
  the release, i.e. Tier 1 access (DG-F01).
- **Repeated queries are untested on the passing noise channel.** They are priced only on the
  subspace channel (N ≤ 16). Nothing was run on the full-rank noise channel that Table 1 marks as
  passing both tiers. Reaching an effective noise level near the representation scale would need
  N ≈ 256–4096 (DG-F02).
- **The result is not new.** FairNVT (TMLR 2026) already reports that averaging noise draws recovers
  the attribute on an isolated-subspace noise design (literature A, flag 1).

**Change** [proposal]. Replace "Tier 1 / Tier 2" with access-named models. Every reported number
carries one tag.

| Tag | Recipient receives | Who this models |
|---|---|---|
| **A1 release** | the permitted release(s) for each target, one draw; labelled training examples of released data | an ordinary recipient |
| **A2 defense-aware** | A1 + mechanism + public parameters (σ, Q if public); trains on examples generated by the mechanism | the standard adaptive recipient |
| **A3 repeated-query (N)** | A2 + N releases of the same person. Valid only where the interface issues fresh noise per query. Persistent per-person tokens give N = 1 by construction. | a recipient who can re-query |
| **A4 white-box population** | A2 + clean (pre-noise) representations of a labelled population sample. The stored durable-guarantees LRT. | a vendor or auditor with pipeline data |
| **A5 insider** | the target's own pre-protection representation | out of scope for removal guarantees; stress test only |

Do not use A4/A5 results to "refute" a guarantee that only claims A1/A2. Report them as separately
labelled stress tests (section 19 of the brief; protocol §3).

**Affected**

- `dg:utils/battery.py`, `experiments/two_tier_certification.py`, `averaging_attack.py`, `README.md`.
- AAAI `paper.tex:203-205, 251-254, 561, 626`.
- PCRL ACS release studies, where persistent tokens are already correct (PA-F18).

**Verification**

- Each verdict in the stored tables can be re-tagged without recomputation.
- A new A2 LRT, fit on noised rows only with the known noise covariance subtracted, matches the
  stored A4 LRT within seed noise. That would show the clean population vectors are not what drives
  the "Tier 2" result. It is cheap but needs stored arrays from the relocated drive.
- For every point marked as passing, report N* (releases needed to breach). It should agree with
  σ/√N interpolation of the stored sweeps within one grid step.

## 2. One held-out utility contract for every method

**Problem**

- **Utility is graded in-sample; attackers are held out.**
  - durable-guarantees fits encoders, erasers and heads on the PCRL *train* partition and grades
    utility on those rows, but attackers on a held-out 25% (DG-F05).
  - Adult clean lift is 0.185 in-sample vs **0.069 held-out**.
  - Readings above 100% are artifacts (easy-cell subspace 102% → 64% out of partition).
- **Conventions differ across arms.**
  - Baselines get the better of their own head and a refit LR probe (`baseline_gauntlet.py:380`).
  - The authors' arm uses its own in-sample head. Six conventions coexist (DG-F06).
- **Degenerate outcomes count as passes.** FARE easy passes at 0% utility; full-rank hard at −7%
  (DG-F09).
- **The PCRL encoder paper's utility claim is false by its own file.** It claims "task accuracy
  within 1pp of the unconstrained backbone". The repo's own comparison file shows that for 2 of 7
  comparable tasks, with gaps up to −12.85 pp, and the comparator is a separately trained model
  (PE-F18) [verified by recount].
- **Selection, tuning and certification share data.**
  - In durable-guarantees they use the same rows and seeds (DG-F07).
  - In PCRL the tabular test splits were used for tuning, so they are spent (PE-F9).

**Change** [proposal]

- **Disjoint roles per seed.** Use these roles, assigned by linkage unit:
  - representation/eraser fit;
  - attacker training;
  - selection/calibration (validation);
  - evaluation.
- **Fixed rules.**
  - One utility-head rule for every arm.
  - The clean reference uses the same architecture.
  - Report absolute task loss, accuracy/AUC and calibration, plus normalised lift with a bootstrap
    CI.
  - A pre-registered minimum clean-lift rule. Normalised utility is not reported when the clean model
    barely beats the constant predictor.
- **A pass requires a utility lower confidence bound above 0.** Degenerate passes are reported
  separately and labelled as constant or collapsed.
- **Fit erasers only on the fit role.** Erasers and projections are never fitted on rows that are
  released or attacked. Johansson (arXiv 2403.16142) inverts projection erasure by anti-clustering when
  it is fitted on the released rows. durable-guarantees currently fits LEACE, Obliviator and Q on all
  rows (DG-F10).
- **Two utility analyses, reported separately:**
  - **Fixed-head:** the method's own deployed head, evaluated on held-out rows.
  - **Refit-head:** a common decoder family refit on the attacker-train role.

  A decoder chosen to suit one method never becomes the universal yardstick.

**Affected**

- `dg:utils/pcrl_io.py:150,188`; `diagnostic.py:205-206`; `baseline_gauntlet.py:380`;
  `mi_ceiling.py:217`.
- PCRL `experiments/run_v2_dataset.py` (split use).
- AAAI `paper.tex:219-223, 263`; NeurIPS draft utility sentence.

**Verification**

- A table that shows in-sample and held-out side by side for every arm, with no ratio whose CI is
  wider than 20 pp.
- An assertion that split-role IDs are disjoint by linkage unit (fixture to add at implementation).

## 3. Make the task-output surface an explicit, gated release with a label-only reference

**Problem**

- The AAAI paper's rule is "both surfaces must clear", but:
  - the 67-configuration audit attacks only the representation;
  - gauntlet verdicts are gated on the representation;
  - the authors' own channels are never output-attacked;
  - output attacks read logits, not ŷ, and the "head" for post-hoc methods is an auditor-fit LR
    (DG-F03).
- Stadler et al. (ICML 2024, §4.1/Fig. 3) already measure label-only "fundamental leakage", which is
  what the AAAI label-coupling predictor computes. The AAAI claim "we contribute its measurement"
  (`paper.tex:171-175`) overclaims (literature A, flag 3).

**Change** [proposal]

- **Declare what is released.**
  - The released task output object per recipient: ŷ, a calibrated score, or a full logit vector.
  - The representation release, if any.
- **Attack separately.** Score R alone, the output alone, and R + output.
- **Use nested references.** Reference predictors for each:
  - the label-only predictor of S from the true y, a population quantity;
  - the predictor of S from the *clean* model's output, with the same output object.
- **Report increments against them.**
  - The output-surface increment is relative to the clean-model output reference, not to chance.
  - Both surfaces gate.

**Affected**

- `dg:experiments/expansion_pipeline.py:150-186`, `honest_reaudit.py:62-80`, `baseline_gauntlet.py:452`,
  `master_gauntlet_table.py:166`, `two_tier_certification.py:117-147`.
- AAAI §Setup/Results.

**Verification**

- Re-gate the stored gauntlet from `out_tier*_max` (no compute; marked as a later recount).
- An output-only attacker must recover at least the label-only reference on a positive-control cell.
  Planned fixture: S = y with noise.

## 4. Replace "worst class / dominant axis" with a contrast-sensitive categorical diagnostic

**Problem**

- **"Dominant axis" misses contrasts.** It is the maximum over class indicators of one-vs-rest R²
  (`origin/main:pcrl/evaluation/certificates.py:47-116`) [verified, IC-F2, PE-F12]. It misses linear
  contrasts between classes.
  - The best contrast R² can be up to (K−1)× the dominant axis. This bound was proven and checked in
    the fixture.
  - At K=10, dominant axis 0.047 and one-hot 0.041 both pass, while one contrast reaches 0.364.
- **The aggregate certificate is computed in float32 on origin/main**
  (`pcrl/purposes/verification.py:77-104`).
  - It understates R² by up to 50% relative (≤0.0033 absolute) on stored audits.
  - In an ill-conditioned synthetic case it certifies R²=0 where the truth is 0.578 [verified, IC-F1].
  - The fixed branch `research/pcrl-submission-finish-v1` casts to float64 but is unmerged.
- **The convex-combination identity is exact algebra; its check was not.** It holds when weights use
  the scored rows and per-class R² is not clipped. The paper's "33/33 validated, residual 0.0021" is
  the float32 artifact, not evidence about the identity (IC-F1, PE-F13).
- **The "12.7× amplification" headline is weak.** It is a ratio of two sub-threshold values, and the
  argmax class is "Joint" applications, not a race category (PE-F14).
- **Unsupported classes are mis-scored.** On origin/main:
  - an absent middle class yields dominant-axis R²=1.0;
  - an absent top class is silently dropped;
  - all-constant labels certify R²=1.0.

  The fix fails closed only if `num_classes` is passed, and singleton classes are scored [verified,
  IC-F3]. In training, an absent class scored R²=1.0 produced the Diabetes "λ≈420 ⇒ rank 24" story
  (PE-F15).
- **The durable-guarantees worst-pair statistic is post hoc.**
  - It takes a max over pairs and then a max over 9 seeds.
  - Its null is a max over 27 draws (0.556; mean 0.536).
  - The ≥3000-row support rule was chosen after seeing the null (DG-F13).

**Change** [proposal]. Report three linear quantities, plus one nonlinear.

1. **Aggregate one-hot explained variance.** The historical definition, kept for reproduction.
2. **Per-class one-vs-rest R²**, each with class support n_k.
3. **Full categorical linear diagnostic.** The largest squared canonical correlation between the
   representation and the centred one-hot attribute with one class dropped:
   ρ₁² = λ_max(Σ_YY^{-1/2} Σ_YZ (Σ_ZZ + εI)^{-1} Σ_ZY Σ_YY^{-1/2}). This is the maximum R² over all
   linear contrasts.

   | Element | Specification |
   |---|---|
   | Covariance support | classes with n_k ≥ n_min in **both** fit and evaluation roles |
   | Regularisation | ε = 1e-6·tr(Σ_ZZ)/d |
   | Precision | float64 |
   | Tolerance | eigenvalues below 1e-10 treated as 0 |
   | Estimation | fitted on the fit role, reported held-out; in-sample for historical reproduction only |

4. **Nonlinear categorical recovery** by the attacker slate: multinomial log-loss reduction and macro
   AUC.

Missing, constant or under-supported classes are reported as **not estimable**, with counts, never as
0 or as "protected".

Every worst-class statistic gets a permutation null at the real class sizes, using the same max-over
rule, and **no max over seeds**. Seeds are averaged, with the seed spread reported.

**Affected**

- `origin/main:pcrl/purposes/verification.py`, `pcrl/evaluation/certificates.py`, `pcrl/training/losses.py`.
- `dg:experiments/run_worstpair_sweep.py:81-98`.
- NeurIPS draft Prop. 4/5 and the 12.7× text.
- AAAI `paper.tex:748-750`.

**Verification**

- Fixtures `fixtures/F01_onehot_identity.py`, `F02_multiclass_contrast.py`, `F03_unsupported_classes.py`
  already demonstrate each defect.
- After a repair, the same fixtures must give:
  - float64 agreement with the independent implementation to 1e-10;
  - ρ₁² equal to the brute-force best contrast;
  - "not estimable" for absent and singleton classes;
  - null rejection ≤ 5% at real class sizes.

## 6. Nested predictors and a defined combination effect

**Problem**

- **Missing nested predictors bias combination effects negative.** A coalition slate without the
  single-recipient predictor (extra features ignored), or an appended-channel slate without the
  ancestor predictor, produces spurious negative combination effects of −0.16 to −0.20 in the
  fixture [verified, IC-F4].
- **Status in the ACS evidence:**
  - The ACS coalition audits used by the withdrawn SaTML manuscript include nested singletons and H
    ancestors [verified, IC-F4, PA-F18].
  - Study 6 lacked the J ancestor (PA-F5).
  - "Catch-up" attackers exist only for some systems. They win 52/54 race endpoints and reverse one
    coalition ordering (PA-F6).
- **Encoder-lineage concatenation attack.**
  - What it fed is documented in PE-F21.
  - Its dominant leak is single-recipient recovery: in 17/33 cells a purpose that disallows the
    attribute already leaks it (PE-F22).
  - Its rebuttal "22/33 → 8/33" is a different model plus a criterion chosen after the results
    (PE-F23).
- **Fitted increments for a constant extension are nonzero.** An appended constant channel gives
  nonzero, mostly negative fitted increments. A paired CI over evaluation people that ignores refit
  randomness covers zero in only 4/6 seeds [verified, IC-F6].

**Change** [proposal]

- **Every multi-view attack slate contains:**
  - all single-view predictors, with other views ignored;
  - all ancestor-view predictors;
  - a prior-only predictor;
  - the exposed-reference predictor.
- **One candidate set per release.** Identical releases receive identical eligible candidates (no
  observer-dependent catch-up). Candidate selection runs on validation; the reported maximum is over
  the locked slate on evaluation.
- **Two distinct estimands:**
  - **absolute coalition recovery** L(S | V_A ∪ V_B);
  - **combination increment** Δ = L(S | best single view) − L(S | V_A ∪ V_B), as a loss reduction.
- **Uncertainty.** Paired over evaluation people, *with refit replicates*. The pure-refit null
  measures the floor.
- **Interpretation.** A negative fitted Δ is reported unclipped, and never read as negative
  information.

**Verification**

- `fixtures/F04_nested_slate.py` and `F06_constant_extension.py`.
- At implementation: a slate-builder unit test asserting every singleton and ancestor ID is present.

## 7. A declared sensitive set and a coherent purpose policy

**Problem**

- **The motivating conflict is not in the code.** The NeurIPS draft motivates HMDA with an
  underwriter who must not see race and an auditor who must. In code, race is disallowed under every
  HMDA purpose, so the conflict never occurs. Appendix H's tasks and attributes do not match the code
  (PE-F20).
- **The rebuttal's union eraser changes what is being tested.** The erase-layer pilot and the
  cross-purpose rebuttal fit **one** LEACE eraser on the union of all purposes' disallowed attributes.
  For Adult this erases the income task label itself. That is a different access policy, not a
  measurement repair (PE-F10, PE-F23).

**Change** [proposal] (the policy table is in the protocol, §2)

- **Declared set and permissions.** A finite declared set S. Each recipient has an explicit allowed
  subset; everything else in S is disallowed.
- **Coalition tests.** They target only the attributes disallowed to **every** member, unless an
  enforceable no-sharing policy is stated.
- **Freeze before measuring.** Permissions are fixed before any recovery measurement.
- **Name the shared-representation limit precisely.** Handing identical information to recipients
  with conflicting permissions cannot realise different access restrictions. That is the limitation,
  not "a shared representation cannot serve multiple tasks".

**Verification**

- The policy table is committed before rescoring.
- Each coalition row lists its jointly-disallowed attributes.
- A unit test flags any target allowed to some member.

## 8. Method fidelity and applicability

**Problem**

- **Two baselines are not what they are called** (MC flags 1–3):
  - PCRL's in-house `LEACEEraser` (`origin/main:pcrl/models/baselines.py:120-181`) is not LEACE: it
    under-erases (in-sample R² 0.9995 → 0.9965, vs < 1e-14 for the official package).
  - PCRL's "R-LACE" is an INLP-style loop. Official RLACE has never been run in either repository.
  - PCRL's "LEACE fails 0/20" table is unaudited.
- **Methods run outside their published setting.**
  - The protected attribute is an input column in every tabular cell of both repos. FNF, Fair PCA and
    official LAFTR were therefore tested outside their papers' setting (MC flag 4; DG-F22).
  - Official LAFTR's binary-attribute code was run on 5-class race (DG-F04).
- **Obliviator never reached its own stopping rule.** So it is not "passed its own test, failed ours"
  (MC flag 7).
- **FARE's certificate is a different guarantee.** It bounds demographic parity, not recovery AUC
  (DG-F04).

**Change** [proposal]

- **Official code, pinned.** `concept-erasure==0.2.4`; official INLP, SPLINCE, FARE and Obliviator at
  the commits in `METHOD_CATALOG.csv`.
- **Two input regimes, declared per arm.** (a) S excluded from X; (b) S included.
- **Binary-only methods** run only on binary cells. Elsewhere they are reported as **N/A**, never 0.
- **Each method's own stated test** (R², DP distance, I(z;c), or its stopping probe) is reported
  alongside the common recovery metric. The headline question is exactly their agreement.

**Verification**

- `METHOD_CATALOG.csv` status column.
- A fidelity reproduction per official method on one of its own published settings before use
  (registered tolerance).
- A post-fit check of Cov(r(X), S) for every linear eraser.

## 11. Data exposure and inference rules

**Problem**

- **Exposure:** see `DATA_EXPOSURE_LEDGER.csv`.

  - The Adult, HMDA and Diabetes PCRL test splits are spent through tuning. durable-guarantees did not

**Change** [proposal] (the rules are in protocol §9)

- Register primary hypotheses and margins.
- Keep intersection-union decisions distinct from simultaneous coverage.
- Any new scoring of spent outcomes is **development evidence**.
- Do not open fresh labels in this phase. Choose a confirmation population (e.g., TX or NY ACS, both
  unused) by an outcome-blind rule before any outcome is seen.

**Verification**

- The registration commit precedes any confirmation-data download.
